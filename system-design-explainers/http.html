HTTP Requests & Status Codes

A request says what to do (method) to which resource (path), with metadata (headers) and optional data (body). The response answers with a status code, headers and an optional body. It travels over the connection that DNS, TCP and TLS set up first.

Anatomy

Request = method + path + headers + body
POST /patients HTTP/1.1
Host: api.example.com
Content-Type: application/json
Authorization: Bearer <token>

{ "name": "John" }
Response = status + headers + body
HTTP/1.1 201 Created
Content-Type: application/json
Location: /patients/124

{ "id": 124, "name": "John" }

Send it twice

Idempotent = repeating the request leaves the same final state

Added
Safe means "doesn't change server state". Every safe method is idempotent, but not the other way round: PUT and DELETE change state, yet repeating them changes nothing further.

Added
1xx and 3xx were empty in the notes. 1xx: 100 Continue, 101 Switching Protocols (WebSocket upgrade). 3xx: 301/308 permanent move, 302/307 temporary move (307/308 keep the method and body), 304 Not Modified (your cached copy is still valid).

      
Added
401 is misnamed. Its official name is "Unauthorized", but it means not authenticated: who are you? 403 means "I know who you are, and you're not allowed".

    

  


  

    
Check yourself

    
Answer out loud before you open each card.

    

      
A user's payment POST timed out. The app retries. How do you avoid charging twice?Show answer
        
Idempotency key. The client sends a unique key; the server stores key → result and returns the stored result for repeats.

      
DELETE /patients/123 returns 204, then 404 on retry. Is DELETE still idempotent?Show answer
        
Yes. Idempotency is about the final state, not identical responses. The patient is gone either way.

      
Logged-in nurse tries to open the admin panel. 401 or 403?Show answer
        
403. The server knows who she is (authenticated) but she lacks permission (not authorized).

      
The gateway waited 30 s and the service never answered. Which code?Show answer
        
504 Gateway Timeout. 502 would mean the service answered with something invalid; 503 means no capacity to try.

      
Creating a patient with an email that already exists. Which code?Show answer
        
409 Conflict. The request is valid but clashes with the current state of the data.

      
Why should a GET handler never change data?Show answer
        
GET is safe and cacheable. Browsers prefetch it, crawlers follow it and caches replay it, so side effects would fire unexpectedly.
