Reverse Proxy, Load Balancer & API Gateway

  • Three layers sit between users and your code.
  • Reverse proxy: protects and optimises traffic for a backend.
  • Load balancer: spreads traffic across healthy instances.
  • API gateway: applies API rules (auth, rate limits, routing) before a service is reached.
  • Real products often do more than one of these.

Each layer adds capabilities

Reverse proxy

"Protect and optimise access to my backend."

  • TLS termination
  • Caching and compression
  • Hides backend IPs, filters bad requests
  • One public entry point

Load balancer

"Spread traffic and survive instance failures."

  • Distribution algorithms (Day 13)
  • Health checks and failover
  • Add or remove instances live

API gateway

"Govern and expose APIs consistently."

  • Authentication and authorisation
  • Rate limits and quotas per client or plan
  • Routing by path or version, request transformation
  • Central logs and metrics

Tools: Nginx, HAProxy, Caddy and Envoy can do proxying and load balancing; Kong, AWS API Gateway, Apigee and Tyk are gateways; AWS ALB (Layer 7) and NLB (Layer 4) are managed load balancers.

    Forward vs reverse proxy

    Same mechanism, different side. A forward proxy hides the clients (company egress proxy, VPN). A reverse proxy hides the servers.

    Corrections and additions

    Corrected

    A server with no proxy in front doesn't return 502. 502 Bad Gateway is produced by a proxy or gateway when its upstream misbehaves. An overloaded bare server shows up as timeouts, refused connections or 503s.

    Corrected

    The server doesn't validate certificates in normal TLS; the client does. The server's TLS cost is the key exchange and signing. Offloading that is what TLS termination saves (validation happens on the server only with mutual TLS).

    Corrected

    "A load balancer is a reverse proxy" is true for Layer 7. Layer 4 balancers often forward TCP connections without terminating them, so they never see HTTP.

    Corrected

    A CDN terminating TLS doesn't remove TLS from your origin. The edge usually opens its own HTTPS connection to the origin. The saving is that it reuses a few long-lived connections instead of one handshake per user.

    Added

    Health checks come in two kinds: active (the balancer polls /health every few seconds) and passive (it notices real requests failing). Connection draining lets in-flight requests finish before an instance is removed for a deploy.

    Added

    Every layer is itself a dependency. Gateways and load balancers run as redundant pairs or managed services; otherwise you've moved the single point of failure, not removed it.

    Which do you actually need?

    SituationUsually enough
    One backend server needing HTTPS, compression, basic protectionReverse proxy (Nginx, Caddy)

    Many microservices needing consistent auth and limitsGateway at the edge + load balancers per service (maybe a service mesh later)
    Users worldwide, lots of static contentAdd a CDN in front

    Check yourself

    Answer out loud before you open each card.

    Where should an expired token be rejected, and why there?Show answer

    At the gateway. One consistent check, and bad requests never cost the services anything.

    You need /payments on an isolated, hardened pool. L4 or L7?Show answer

    L7. Only an HTTP-aware balancer can see the path and route by it.

    Long-lived HTTP/2 connections leave one instance overloaded behind an L4 balancer. Why?Show answer

    L4 balances connections, not requests. One busy connection carrying many streams sticks to one instance.

    A CDN serves logo.png. What reaches your origin on a cache hit?Show answer

    Nothing. The edge answers from its cache until the TTL expires.

    An instance crashes. What does the load balancer do?Show answer

    Health checks fail, so it's removed from the pool and traffic goes to healthy instances; it rejoins after recovering.

    Does a simple internal app with two servers need an API gateway?Show answer

    Usually not. A load balancer (or Nginx) is enough. Add layers for real needs, not for the diagram.
