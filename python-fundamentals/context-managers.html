Context managers

  • with X as v: calls X.__enter__() before the block (its return value becomes v) and X.__exit__() after it, no matter how the block ends.
  • That makes with the standard way to acquire and release: files, locks, database transactions, network connections, temporary settings.
  • __exit__ receives the exception (if any). Returning a true value swallows it; usually you return False and let it propagate.
  • @contextmanager lets you write one as a generator: code before yield is enter, code after (in finally) is exit.

Why put the code after yield inside finally?Show answer
        
If the with-block raises, the exception is thrown into the generator at the yield. Without try/finally the cleanup lines after yield would be skipped.

      
What does with open(p) as f: guarantee that f = open(p) doesn't?Show answer
        
f.close() is called when the block ends, even on an exception or return. With plain open() you must close it yourself in a finally.
