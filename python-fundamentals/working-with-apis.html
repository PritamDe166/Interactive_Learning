Working with APIs

  • A web API is a URL that returns data (usually JSON) instead of a page. You send an HTTP request (method, URL, headers, body) and get a response (status code, headers, body).
  • The requests library: requests.get(url, params=…, headers=…, timeout=…), requests.post(url, json=…).
  • Check the outcome with r.status_code or r.raise_for_status(), then decode with r.json(), which gives plain dicts and lists.
  • Always set a timeout, keep secrets out of code, and expect lists to come in pages.

Cheat-sheet

    
    
      
  • Read data→r = requests.get(url, params={...}, timeout=10)
    • 
      
  • Send data→requests.post(url, json=payload, timeout=10) (sets the JSON header for you)
    • 
      
  • Did it work?→r.raise_for_status(), or check r.ok / r.status_code
    • 
      
  • Body as Python→r.json(); r.text for raw text
    • 
      
  • API keys and tokens→From an environment variable: os.environ["API_TOKEN"], never in the code
    • 
      
  • Many calls to one host→with requests.Session() as s: reuses connections and headers
    • 
      
  • Long lists→Loop on the API's next page / cursor until it's empty

Reference: requests in a real script

    
import osimport requests   # pip install requests (inside your venv)BASE = "https://api.example.com/v1"AUTH = {"Authorization": f"Bearer {os.environ['API_TOKEN']}"}try:    r = requests.get(f"{BASE}/patients", params={"city": "Pune"}, headers=AUTH, timeout=10)    r.raise_for_status()except requests.Timeout:    print("server too slow, try later")except requests.HTTPError as e:    print("API said no:", e.response.status_code, e.response.text)else:    for p in r.json()["items"]:        print(p["name"])

    
StatusMeaningTypical reaction

      
200 / 201 / 204OK / created / no contentuse the body (none for 204)

      
400 / 422your request is invalidfix the data; read the error body

      
401 / 403not authenticated / not allowedcheck the token or permissions

      
404no such resourcehandle "not found"

      
429too many requestswait (Retry-After header) and retry

      
500 / 502 / 503server-side problemretry later with backoff

What's the difference between params= and json= in requests?Show answer
        
params go into the URL query string (?city=Pune); json is serialised into the request body with a Content-Type: application/json header (typical for POST/PUT).

      
import json\nprint(json.loads('{"next": null}')["next"] is None)Show answer
        
True. JSON null → None.

      
Does requests.get() raise an exception for a 404?Show answer
        
No. It returns a response with status_code 404. Only network problems (timeouts, DNS, refused connections) raise. Call r.raise_for_status() to turn 4xx/5xx into an HTTPError.
