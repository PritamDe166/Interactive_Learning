OOP deeper: dunders, properties, dataclasses

  • Python's operators and built-ins call dunder methods (double underscore): a + b → a.__add__(b), len(x) → x.__len__(), print(x) → x.__str__().
  • Define __repr__ (for developers) and optionally __str__ (for users) so objects print usefully.
  • @property makes a method read like an attribute; @classmethod gets the class (alternative constructors); @staticmethod gets neither.
  • @dataclass writes __init__, __repr__ and __eq__ from type-annotated fields: the quickest way to a clean data class.

Cheat-sheet

  • Objects print as <… at 0x…>→Add __repr__ (or use @dataclass)
  • Mostly-data class→@dataclass; frozen=True for immutable, order=True for sorting
  • Validate on assignment / computed value→@property (+ @x.setter)
  • Build an object from another format→@classmethod def from_json(cls, data):
  • Helper that needs no self or cls→@staticmethod, or just a module-level function
  • Make == work→__eq__ (and __hash__ if used in sets/dict keys)
  • Different classes, same method name→Polymorphism: call it without checking the type
