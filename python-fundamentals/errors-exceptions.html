Errors & exceptions

  • An exception is an object Python raises when something goes wrong. It stops the current line and travels up the call stack until something catches it.
  • try runs risky code; except SomeError handles that error; else runs only if nothing went wrong; finally always runs.
  • Catch specific exceptions (ValueError, KeyError), not everything, so real bugs still show up.
  • Use raise to signal a problem yourself. Read a traceback from the bottom: the last line says what went wrong.

Added
Gap topic: the repo uses int(input(...)) in many exercises but never handles a non-number, so any typo crashes the program. Wrapping those calls is the first real use of try/except.

      
Added
Custom exceptions: class SlotTakenError(Exception): pass then raise SlotTakenError("9:00"). Callers can catch exactly that.

      
Added
Re-raising: inside except, a bare raise re-raises the same error after logging it; raise NewError(...) from e wraps it while keeping the original cause.

      
Updated
Recent versions: Python 3.11 added except* and ExceptionGroup for errors from several tasks at once, plus e.add_note(). Python 3.14 lets you drop the brackets when catching several types: except ValueError, TypeError: (PEP 758).
