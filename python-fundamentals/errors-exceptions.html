Errors & exceptions

  • An exception is an object Python raises when something goes wrong. It stops the current line and moves up through the functions that called it (the call stack) until some code catches it.
  • try runs risky code. except SomeError handles that error. else runs only if nothing went wrong. finally always runs.
  • Catch specific exceptions (ValueError, KeyError), not everything, so real bugs still show up.
  • Use raise to signal a problem yourself. Read a traceback from the bottom: the last line says what went wrong.

A traceback, read bottom-up

      
Traceback (most recent call last):  File "app.py", line 8, in <module>      # 3. started here    outer()  File "app.py", line 5, in outer         # 2. passed through    return inner() + 1  File "app.py", line 2, in inner         # 1. happened here    return int("x")ValueError: invalid literal for int() with base 10: 'x'

    

      
The first real use of try/except: int(input(...)) crashes on any typo. Wrapping it lets you handle a non-number and ask again.

      
Custom exceptions: class SlotTakenError(Exception): pass then raise SlotTakenError("9:00"). Callers can catch exactly that.

      
Re-raising: inside except, a bare raise (raise with nothing after it) raises the same error again, for example after you log it. raise NewError(...) from e raises a new error and keeps the original one as its cause.

      
Recent versions: Python 3.11 added except* and ExceptionGroup, for handling errors from several tasks that run at the same time. It also added e.add_note() to attach extra text to an error. Python 3.14 lets you drop the brackets when catching several types: except ValueError, TypeError: (PEP 758).
