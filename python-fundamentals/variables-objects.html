Variables, Objects & Types

  • A variable is a name that points to an object. It is not a box that holds the value.
  • Every value is an object with a type and an identity (id()). Names have no type.
  • Assignment copies the arrow, never the object. Two names can point to one object.
  • Immutable objects (int, float, str, bool, tuple) never change; mutable ones (list, dict, set) change in place.

Cheat-sheet

  • b = a→Second name, same object (no copy)
  • Change a list through one name→Every name pointing to it sees the change
  • Need an independent list→b = a.copy() or list(a)
  • "Changing" an int, str or tuple→Creates a new object; the name moves
  • Compare values / check identity→== / is (use is only for None)
  • Empty, zero or None in an if→False; everything else is True (even "False")

Triple-quoted text isn't a comment. VariablesAndDataTypes.py calls '''…''' a multi-line comment, but it's a string literal that Python creates and throws away (at the top of a function it becomes the docstring). Real comments start with #.

Corrected

It's isinstance, not isInstance (the comment in Type_Conversion.py). Python names are case-sensitive. And int(4.5) doesn't round: it truncates toward zero, so int(-4.5) is -4.

Added

Your id(list1) == id(list2) example is aliasing. In UtilityBuiltInFunctions.py both ids print the same number because list2 = list1 creates a second name, not a second list. id() is an object's identity while it lives (its memory address in CPython).

Added

Never use is to compare numbers or strings. CPython reuses some small ints and short strings, so is may look like it works and then fail with other values. Use == for values; is for None (if x is None).

Added

Python has no constants. By convention, UPPER_CASE names (MAX_VISITS = 5) mean "don't reassign". Type hints (age: int = 34) are documentation for tools like mypy; Python doesn't enforce them at runtime.
