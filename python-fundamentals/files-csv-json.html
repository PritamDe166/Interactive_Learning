Files, CSV & JSON

  • open(path, mode) returns a file object. Mode "r" reads, "w" erases then writes, "a" appends to the end.
  • Always use with open(...) as f:. The file is closed automatically when the block ends, even after an error.
  • Pass encoding="utf-8", and newline="" for CSV files.
  • csv.DictReader turns each row into a dict keyed by the header. Values are always strings.
  • json: dump/load work with files, dumps/loads with strings (the s is for string).

Cheat-sheet

  • Read a text file→with open(p, encoding="utf-8") as f: for line in f:
  • Add to a file without losing it→Mode "a"; "w" erases
  • CSV with a header row→csv.DictReader / csv.DictWriter, and newline=""
  • Numbers from CSV→Convert: int(row["fee"])
  • Save / load settings or API data→json.dump(obj, f, indent=2) / json.load(f)
  • JSON in a string (e.g. an HTTP body)→json.loads(text) / json.dumps(obj)
  • Paths that work from any folder→Path(__file__).parent / "data" / "notes.txt" (pathlib)

file_read_write_using_Open.py opens notes.txt with "w", which erases the notes the other scripts wrote and replaces them with one line. Easy to lose data this way: use "a", or write to a new file.

csv_read.py, ReadCsvHeaders: for row in header loops over the column names of the header row, not rows. Name it for column in header.

Corrected

Paths: every script uses "File read and write/files repository/...", which only works when you run Python from the repo root. Build the path from the script's location with pathlib.Path(__file__).parent.

Updated

Encoding: none of the repo's open() calls pass encoding=. Before Python 3.15 the default depended on the OS (often cp1252 on Windows), so non-English names could break. Python 3.15 (Oct 2026) makes UTF-8 the default (PEP 686), but passing encoding="utf-8" keeps code correct on older versions too.

Added

Naming: functions like ReadCsvAsDictionaries use PascalCase; PEP 8 uses snake_case for functions (read_csv_as_dicts) and PascalCase for classes.

What does with guarantee?Show answer

The file is closed when the block ends, whether it ends normally, with return, or with an exception. It's a context manager (its own page in Part 5).

import json; print(json.loads('[1, "a", null]'))Show answer

[1, 'a', None]. JSON null becomes None.

import csv, io\nprint(next(csv.reader(io.StringIO('a,"b,c",d'))))Show answer

['a', 'b,c', 'd']. The csv module handles quoted commas; split(",") wouldn't.

import json; print(json.dumps({"b": 1, "a": 2}, sort_keys=True))Show answer

{"a": 2, "b": 1}. sort_keys gives stable output, handy for diffs and tests.
