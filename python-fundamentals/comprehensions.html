Comprehensions

  • A comprehension builds a new list from an existing sequence in one expression: [f * 2 for f in fees].
  • Read it as what to keep · for each item · optional filter: [expr for x in items if cond].
  • Same idea for dicts {k: v for ...} and sets {x for ...}; with round brackets it becomes a lazy generator expression.
  • Use one when the loop only builds a collection. If it needs several statements, keep the normal loop.

Cheat-sheet

    
    
      
  • Transform every item→[f(x) for x in xs]
    • 
      
  • Keep only some items→[x for x in xs if cond]
    • 
      
  • Choose between two values per item→[a if cond else b for x in xs]
    • 
      
  • Build a lookup table→{x.id: x for x in items}
    • 
      
  • Distinct values→{x.city for x in items}
    • 
      
  • Feeding sum / max / any / all→Generator expression: sum(x.fee for x in items)

  • Loop body needs several statements or side effects→Keep the normal for loop

Added
Gap topic: the repo builds lists with append in loops (Loops.py, Lists_exercises.py) but never uses comprehensions, which are everywhere in real Python code and in the Notion learning plan (Week 1).

      
Added
Own scope: the loop variable of a comprehension does not leak out (unlike a for loop). Since Python 3.12 list/dict/set comprehensions are inlined for speed (PEP 709), but this rule hasn't changed.

      
Added
Readability rule: one for and one if is easy to read. Two nested fors is the usual limit; beyond that, write a loop or a helper function.

print([c.upper() for c in "abc"])Show answer
        
['A', 'B', 'C']. Any iterable works, including a string.

      
print(len([x for x in range(10) if x % 3 == 0]))Show answer
        
4. 0, 3, 6 and 9.

      
print({k: v for k, v in [("a", 1), ("a", 2)]})Show answer
        
{'a': 2}. The later value for the same key wins.

      
x = 5; y = [x for x in range(3)]; print(x)Show answer
        
5. The comprehension's x is separate and doesn't overwrite the outer one.

      
print(any(n > 3 for n in [1, 5, 2]))Show answer
        
True. A generator expression straight into any().

      
print(type((n for n in [1])).__name__)Show answer
        
generator. Round brackets don't make a "tuple comprehension".
