Built-in functions toolbox

  • Built-ins are always available, no import needed. Most take any iterable: list, tuple, string, set, dict, range, generator.
  • Some return a value straight away (len, sum, sorted); others return a lazy iterator (reversed, enumerate, zip, map) you loop over or wrap in list().
  • sorted() returns a new list; list.sort() changes the list and returns None.
  • round() rounds halves to the even neighbour: round(2.5) is 2.

Cheat-sheet

  • Count / total / extremes→len sum min max
  • Sorted copy vs sort in place→sorted(xs) vs xs.sort() (returns None)
  • Loop with a counter→enumerate(xs, start=1)
  • Walk two lists together→zip(a, b); add strict=True if lengths must match
  • Any / every item passes a test→any(...) / all(...) with a generator expression
  • Money rounding must be exact→decimal.Decimal with ROUND_HALF_UP, not float + round()
  • What can this object do?→dir(obj), help(obj)

Corrected

round() in BuiltinFunctions_Math_Numbers.py: the examples (4.56756, 8.542, -13.349) never hit a half, so they hide the surprise: round(2.5) is 2, round(0.5) is 0. Also round(2.675, 2) gives 2.67, because 2.675 can't be stored exactly as a float.

Added

Lazy results print oddly: print(reversed(nums2)) in the repo shows <list_reverseiterator object at 0x…>, not the items. Wrap it in list() or loop over it, as the next line does.

Added

zip() hides length mismatches: the repo zips 3 fruits with 4 numbers and the 4th number vanishes silently. Use zip(..., strict=True) when they must match.

Added

help() and dir() are for the interactive prompt. In scripts they print pages of text; in an editor, hover or go-to-definition is quicker.
