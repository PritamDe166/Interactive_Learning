Week 3 · H21 · Caching & CDN

CDN & HTTP Caching

  • A CDN keeps copies of your responses on edge servers close to users.
  • Pull CDNs fetch from your origin on the first miss; push CDNs get files uploaded ahead of time.
  • The Cache-Control header decides who may store a response (browser, CDN) and for how long.
  • ETag + 304 lets a stale copy be re-validated without downloading it again.
  • Static files get a hash in the name and a one-year cache; HTML stays short-lived. Purge is the emergency brake.

4Revise in two minutes

Cheat-sheet

  • Hashed JS/CSS/fonts/images→public, max-age=31536000, immutable
  • HTML pages→no-cache + ETag (always revalidate)
  • Per-user data (account, cart)→private (never the CDN)
  • Secrets, one-time tokens→no-store
  • CDN may cache longer than browsers→max-age=60, s-maxage=3600
  • Wrong content already cached→Purge the URL (or tag)
  • Huge, scheduled release→Push / pre-warm the CDN

5Test yourself

Which pattern fits?

Explain it out loud

Answer before you open each card.

Why cache app.4f2c.js for a year but index.html for 0 seconds?Show answer

The hashed file can never change (a new build gets a new name), but the HTML is what points to the new name, so it must always be fresh.

no-cache vs no-store?Show answer

no-cache: keep a copy but revalidate before use (cheap 304s). no-store: keep nothing.

A user's account page shows up for another user. Which header was wrong?Show answer

It was cacheable by the CDN (public or missing private). Per-user responses need private or no-store.

What does a 304 save, and what doesn't it save?Show answer

It saves the download (no body). It still costs a round trip to whoever answers the revalidation.

Pull CDN at a 9 AM global launch: what goes wrong?Show answer

Every edge misses at once and all of them hit the origin together. Push or pre-warm the files first.

Why prefer new file names over purges for static files?Show answer

Purges take time to spread and can be missed by browsers that already cached the old file. A new URL is new everywhere immediately.
