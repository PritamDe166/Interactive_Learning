Caching Failure Modes

  • A cache hides load from the database, until the moment it stops hiding it.
  • Stampede: one hot key expires and every request reloads it at once.
  • Avalanche: many keys expire together, or a cache node dies.
  • Penetration: lookups for keys that don't exist always reach the database.
  • Hot key and stale data round out the set; each has a standard fix.

4Revise in two minutes

Cheat-sheet

  • Hot key expires, DB spikes→Stampede: single-flight / lock, stale-while-revalidate
  • Many servers, still a spike→Distributed lock (SET NX) or refresh-ahead
  • Spike at the same time every day→Avalanche: TTL jitter, staggered warm-up
  • Cache node restarted, DB on fire→Avalanche: replicas, persistence, rate-limit the DB path
  • Misses for IDs that don't exist→Penetration: cache NULL briefly, Bloom filter, validate input
  • One node hot, others idle→Hot key: L1 copy, replicate or split the key
  • Users see old values→Stale data: delete on write + TTL (H17)

5Test yourself

Which pattern fits?

Explain it out loud

Answer before you open each card.

Stampede vs avalanche: what's the difference?Show answer

Stampede: many requests for one key at once. Avalanche: many keys missing at once (same TTL or cache loss).

Single-flight solves the stampede on one server. Why can 20 servers still hurt?Show answer

Each server has its own lock, so up to 20 loads run. Use a distributed lock, SWR or refresh-ahead if 20 is too many.

What does stale-while-revalidate trade away?Show answer

Freshness for a short window. Users get the old value instantly while one refresh runs; wrong for balances or stock at checkout.

How does a Bloom filter stop penetration, and what can't it do?Show answer

It says "definitely not present" or "maybe present". Definite misses skip the DB. It can give false positives, never false negatives, and can't easily delete.

Why add jitter instead of just a longer TTL?Show answer

A longer TTL only moves the cliff. Jitter spreads expiries out so they never line up.

The cache cluster restarts during peak. What protects the database?Show answer

Replicas and persistence so the cache comes back warm, plus rate limiting / circuit breakers on the DB path so a cold cache can't flood it.
