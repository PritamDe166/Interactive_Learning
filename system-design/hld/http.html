Week 1 / H2 / Networking Fundamentals

HTTP Requests & Status Codes

  • A request says what to do (method) to which resource (path).
  • It carries metadata (headers) and optional data (body).
  • The response answers with a status code, headers and an optional body.
  • The request and response travel over a connection. First DNS finds the server's IP, then TCP and TLS set up the connection.

1Learn: what a request and response look like

Anatomy

Request = method + path + headers + body
POST /patients HTTP/1.1
Host: api.example.com
Content-Type: application/json
Authorization: Bearer <token>

{ "name": "John" }
Response = status + headers + body
HTTP/1.1 201 Created
Content-Type: application/json
Location: /patients/124

{ "id": 124, "name": "John" }

2Compare: methods and HTTP versions

Methods at a glance

MethodPurposeSafeIdempotentNote
GETRead a resourceYesYesCacheable; never change data in a GET handler
HEADLike GET, headers onlyYesYesCheck size or freshness without downloading
OPTIONSAsk what is allowedYesYesUsed by browsers for a CORS preflight: a check, before a cross-site request, that the server allows it
POSTCreate, or run an actionNoNoMake it safe to retry with an idempotency key
PUTReplace the whole resourceNoYesCan also create at a client-chosen URL
PATCHChange part of a resourceNoDepends"Set age = 41" is idempotent (repeating it changes nothing more); "append to list" is not (each repeat adds another item)
DELETERemove a resourceNoYesSecond call may return 404, but the state is the same

Safe means "doesn't change server state". Idempotent means "repeating the request leaves the same final state". Every safe method is idempotent, but not the other way round: PUT and DELETE change state, yet repeating them changes nothing further.

1xx and 3xx in practice. 1xx: 100 Continue, 101 Switching Protocols (WebSocket upgrade). 3xx codes: 301 and 308 mean a permanent move. 302 and 307 mean a temporary move. 307 and 308 keep the original method and body. 304 Not Modified means your cached copy is still valid.

Check yourself

    
Answer out loud before you open each card.

    

      
A user's payment POST timed out. The app retries. How do you avoid charging twice?Show answer
        
Idempotency key. The client sends a unique key; the server stores key → result and returns the stored result for repeats.

      
DELETE /patients/123 returns 204, then 404 on retry. Is DELETE still idempotent?Show answer
        
Yes. Idempotency is about the final state, not identical responses. The patient is gone either way.

      
Logged-in nurse tries to open the admin panel. 401 or 403?Show answer
        
403. The server knows who she is (authenticated) but she lacks permission (not authorized).

      
The gateway waited 30 s and the service never answered. Which code?Show answer
        
504 Gateway Timeout. 502 would mean the service answered with something invalid; 503 means no capacity to try.

      
Creating a patient with an email that already exists. Which code?Show answer
        
409 Conflict. The request is valid but clashes with the current state of the data.

      
Why should a GET handler never change data?Show answer
        
GET is safe and cacheable. Browsers load GET links early (prefetch), search crawlers follow them and caches repeat them. So any data change in a GET handler (a side effect) would happen when nobody expected it.
