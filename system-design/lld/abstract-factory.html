Abstract Factory

  • An interface for creating a family of related objects without naming their concrete classes.
  • Use it when the objects must match: Azure storage with an Azure queue, not Azure storage with an AWS queue.
  • Swapping the whole family is one line: the factory you pick at startup (cloud in production, local fakes in development).
  • The trade-off: adding a new kind of product means editing every factory.

4Revise in two minutes

    
Cheat-sheet

    
    
      
  • Several objects must come from the same vendor, theme or environment→abstract factory: one CreateX() per product kind
    • 
      
  • Swap everything for tests or local development→a LocalDevFactory / fake factory, chosen at startup
    • 
      
  • You only create one kind of object→factory method or DI; abstract factory is overkill
    • 
      
  • New product kinds are added often→expect to edit every factory; consider per-product DI registrations instead
    • 
      
  • ASP.NET Core→often expressed as an extension method that registers the whole family: services.AddAzureInfrastructure()
    • 
      
  • Interview: "factory method vs abstract factory?"→one product by inheritance vs a matching family by composition
    •

Explain it out loud

    
Answer before you open each card.

    

      
What does "family of related objects" mean? Give an example.Show answer
        
Objects designed to work together and that must come from the same variant: a SQL Server connection + command + parameter, or Azure blob + Service Bus + Key Vault clients, or a dark-theme button + checkbox + menu.

      
How does the pattern stop mixing families?Show answer
        
Client code never names a concrete class; it only calls methods on the one factory it was given. Every product therefore comes from that factory's family.

      
What's the main weakness?Show answer
        
Adding a new product kind changes the factory interface, so every concrete factory must be edited. Adding a new family is easy; adding a new kind is not.

      
Where do you choose the concrete factory in an ASP.NET Core app?Show answer
        
Once, at startup (Program.cs), based on configuration or environment. Register it as ICloudFactory (or register each product from it); nothing else in the app decides.

      
Name an abstract factory in .NET itself.Show answer
        
DbProviderFactory (CreateConnection, CreateCommand, CreateParameter).
