OOP Pillars in C#

  • Encapsulation: state stays private; the only way in is a method that enforces the rules.
  • Abstraction: callers see what an object does, not how (interfaces, abstract classes).
  • Inheritance: one base class, many interfaces; constructors run base first.
  • Polymorphism: with override the object decides at runtime; with new the variable's type decides; overloads are picked by the compiler.
  • Interview favourites: interface vs abstract class, protected internal vs private protected, class vs struct.

3Revise in two minutes

Cheat-sheet

  • Public setter with no rule→not encapsulation: make it a method that validates
  • Callers shouldn't know how it works→abstraction: an interface or abstract class in front
  • Related classes share code and state, a few steps differ→abstract base class (template method)
  • Unrelated classes share a capability, or you need to swap / fake it→interface
  • Behaviour must follow the real object→virtual in the base + override
  • You see new on a method, or warning CS0108→hiding: the variable's type decides; usually a bug
  • Same name, different parameters→overloading, chosen at compile time
  • Subclasses only, and only in this assembly→private protected (intersection)
  • Subclasses anywhere, or anyone in this assembly→protected internal (union)
  • Small immutable value with no identity→struct / record struct; entities are classes

Defaults: members are private unless stated; top-level types are internal. A static class can't be instantiated or inherited; a sealed class can't be inherited, and sealed override stops one method being overridden further.

Encapsulation vs abstraction: encapsulation protects data (private state, guarded changes); abstraction hides complexity (a small contract in front of the details). They work together.

Covariant returns (C# 9): an override may return a more derived type than the base method declared.

4Test yourself

Which pillar or feature is it?

Explain it out loud

Answer before you open each card.

Encapsulation vs abstraction in one sentence each?Show answer

Encapsulation: private state that changes only through methods with rules. Abstraction: callers use a small contract and don't know how it works inside.

LabReport declares new Footer(). What does this return?Report r = new LabReport(); r.Footer();Show answer

Report.Footer() ("generic footer"). With hiding, the variable's compile-time type decides. If Footer were virtual and LabReport used override, you'd get "lab footer".

In what order do constructors run for new UrgentSmsNotifier()?Show answer

Base first: Notifier, then SmsNotifier, then UrgentSmsNotifier. : base(...) chooses which base constructor and passes its arguments.

When would you choose an abstract class over an interface?Show answer

When related classes share code or state and a constructor, with a few steps left abstract. Choose an interface for a capability unrelated classes share, or to swap implementations and fake them in tests.

protected internal vs private protected?Show answer

protected internal = same assembly or any subclass (union). private protected = subclasses in the same assembly only (intersection).

Why can't you call a default interface method through the class variable?Show answer

The class didn't implement it, so it's only a member of the interface: svc.Audit() gives CS1061; ((IAuditable)svc).Audit() works.
