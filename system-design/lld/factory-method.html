Simple Factory & Factory Method

  • Both answer one question: who decides which class to new? Callers shouldn't; they should ask for "a notifier" and get the right one.
  • Simple factory: one class with a Create(type) method and a switch. Not a GoF pattern, but the most common.
  • Factory method (GoF): a base class calls an abstract CreateX(); each subclass decides what to create.
  • In ASP.NET Core the DI container is usually your factory: inject INotifier, or pick by key with keyed services.

4Revise in two minutes

    
Cheat-sheet

    
    
      
  • The same if / switch → new appears in several callers→simple factory: move it to one Create(type)
    • 
      
  • A base class runs a fixed algorithm but one object in it varies→factory method: abstract CreateX(), overridden by subclasses
    • 
      
  • Choosing an implementation by a key at runtime in ASP.NET Core→keyed services (AddKeyedScoped) or a dictionary of IEnumerable<INotifier>
    • 
      
  • Need a new object per call but want DI to build it→inject a factory (IHttpClientFactory, Func<T>, ActivatorUtilities)
    • 
      
  • Only ever one implementation→no factory: just inject it
    • 
      
  • Interview: "factory method vs simple factory?"→parameter decides vs subclass decides; factory method needs no switch
    • 
    

    

      
Why "factory method" confuses people: any static method that returns a new object (Guid.NewGuid(), TimeSpan.FromMinutes()) is casually called a factory method. The GoF pattern is narrower: an overridable creation step inside a class, so subclasses choose the product.

      
Link to SOLID: a simple factory still breaks open-closed (edit the switch for each new type) but contains the damage to one file. Factory method and keyed DI keep the code closed: new types are new classes. And callers depend on INotifier, not concrete classes (dependency inversion).

Explain it out loud

    
Answer before you open each card.

    

      
What problem does any factory solve?Show answer
        
It takes the decision "which concrete class?" away from the code that uses the object. Callers depend on an interface; the choice of new lives in one place.

      
Simple factory vs factory method in one sentence each.Show answer
        
Simple factory: one method takes a parameter and switches to pick the class. Factory method: a base class declares an abstract creation method and each subclass returns its own product.

      
Why does the factory method pattern avoid editing old code when a type is added?Show answer
        
There's no switch to extend: the new variant comes with its own subclass that overrides CreateNotifier(). Existing classes don't change.

      
What should a simple factory do with an unknown type?Show answer
        
Fail fast with a clear exception (ArgumentOutOfRangeException), or return a deliberate default / Null Object if the business allows it. Never return null silently.

      
How would you pick a notifier by name in ASP.NET Core 8 without writing a switch?Show answer
        
Register keyed services (AddKeyedScoped<INotifier, SmsNotifier>("sms")) and resolve with GetRequiredKeyedService<INotifier>(channel) or [FromKeyedServices("sms")].
