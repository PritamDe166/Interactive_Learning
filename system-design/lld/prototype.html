Prototype

  • Create a new object by copying an existing, already configured one (the prototype) instead of building it from scratch.
  • Worth it when setting an object up is expensive (loaded from a database, many steps) and you need many slightly different copies.
  • The whole pattern hinges on one question: shallow or deep copy? Get it wrong and editing the copy silently changes the original.
  • In C#: MemberwiseClone() and record with expressions are both shallow.

Strings and value types are safe: string is immutable and int, decimal, DateTime are copied by value, so giving the copy a new title never affects the original. The danger is mutable reference types: lists, dictionaries and your own classes.

      
Not everything should be deep-copied. The Doctor is a shared entity: every consultation should point to the same doctor. Decide per field: copy what the clone owns, share what it only refers to.

Cheat-sheet

    
    
      
  • Building an object is expensive and you need many variants→configure one prototype, then clone and tweak
    • 
      
  • Object has only value types and strings→shallow copy (MemberwiseClone, record with) is enough
    • 
      
  • Object holds lists or mutable objects the copy may change→deep-copy those fields explicitly (copy constructor or Clone())
    • 
      
  • Field is a shared entity (doctor, tenant)→keep the reference; don't clone it
    • 
      
  • Need templates by name→prototype registry: Dictionary<string, Template> + Clone()
    • 
      
  • Tempted by ICloneable→avoid it: it doesn't say shallow or deep; write your own typed Clone()
    • 
      
  • Deep copy via JSON serialise / deserialise→quick, but slow and drops non-serialisable state; fine for tests
    •

Explain it out loud

    
Answer before you open each card.

    

      
What problem does the prototype pattern solve?Show answer
        
Creating many similar objects when setting one up is expensive or complicated: you configure one, then copy it, instead of repeating the setup. Callers also don't need to know the concrete class to copy it.

      
Shallow vs deep copy in one sentence each.Show answer
        
Shallow: a new object whose fields hold the same references as the original. Deep: a new object whose mutable referenced objects are copied too.

      
Is a record's with expression a deep copy?Show answer
        
No. It copies the record's fields (shallowly) and changes the ones you list. A List property is shared between the original and the new record.

      
Why is ICloneable discouraged?Show answer
        
It returns object and its contract doesn't say whether the copy is shallow or deep, so callers can't rely on it. Microsoft's design guidelines recommend not implementing it in public APIs.

      
Should a cloned consultation also clone its Doctor?Show answer
        
No: the doctor is a shared entity the consultation refers to. Clone what the copy owns (its checks, its prescriptions); share what it only points to.
