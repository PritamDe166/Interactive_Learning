UML: Class and Sequence Diagrams

  • UML is the standard picture language for designs. LLD mostly needs two diagrams: class diagrams (structure) and sequence diagrams (who calls whom, in order).
  • A class box has three parts: name, attributes and operations. Symbols show visibility: + public, − private, # protected, ~ package.
  • Six relationships, weakest to strongest: dependency, association, aggregation, composition, generalization (inheritance) and realization (implements).
  • Arrowheads point at what is depended on; diamonds sit on the whole. Filled diamond = the parts die with the whole.
  • Multiplicity (1, 0..1, *, 1..*) says how many objects take part at each end.

3Revise in two minutes

Cheat-sheet

  • Class uses another only as a parameter or local→dependency: dashed line, open arrow A ..> B
  • Class keeps a reference in a field or property→association: solid line, arrow shows who knows whom A --> B
  • Whole has parts that live on or are shared→aggregation: hollow diamond on the whole Whole o-- Part
  • Whole creates and owns its parts; they die with it→composition: filled diamond on the whole Whole *-- Part
  • class B : A (is-a)→generalization: solid line, hollow triangle at the parent A <|-- B
  • class B : IA (implements)→realization: dashed line, hollow triangle at the interface IA <|.. B
  • Not sure if it's aggregation→draw a plain association and say the lifetime out loud
  • Sequence: caller waits for the result→solid line, filled arrowhead; reply is a dashed line
  • Sequence: publish an event, don't wait→solid line, open arrowhead (async)
  • Sequence: if / else, optional step, loop→Draw an alt / opt / loop frame (a labelled box around the messages) with a [guard], the condition in square brackets

14 diagrams, two families: UML 2.5 has 7 structural diagrams (class, object, component, package, deployment, composite structure, profile) and 7 behavioural ones (sequence, activity, state machine, use case, communication, timing, interaction overview). State machines pair with the State pattern; use cases list who can do what.

Aggregation is loosely defined. UML gives "shared aggregation" almost no extra meaning over an association, so many designers skip the hollow diamond. Composition has a clear meaning: exclusive ownership and a shared lifetime.

Draw just enough. In an LLD interview, show key attributes, the operations that matter, interfaces for the parts that vary, and deliberate relationships. Skip getters, setters and private helpers.

4Test yourself

Which relationship is it?

Explain it out loud

Answer before you open each card.

Which end does the diamond go on, and which way does the inheritance triangle point?Show answer

The diamond sits on the whole (the owner). The triangle points at the parent class or interface. Rule of thumb: arrowheads point at what is depended on.

Aggregation vs composition: what single question decides it?Show answer

"If I delete the whole, do the parts go too, and can a part belong to two wholes?" Parts die and are exclusive → composition. Parts survive or are shared → aggregation (or a plain association).

What's the difference between dependency and association?Show answer

A dependency is temporary: the other class appears as a parameter, local variable or static call. An association is structural: the class keeps a reference in a field or property.

Read Order "1" *-- "1..*" OrderLine aloud.Show answer

An order is composed of one or more order lines; each order line belongs to exactly one order and is deleted with it.

How do you show a call that doesn't wait for a reply in a sequence diagram?Show answer

An asynchronous message: solid line with an open arrowhead. A synchronous call has a filled arrowhead; replies are dashed.

Which two diagrams would you draw first in an LLD interview, and in what order?Show answer

The class diagram first (entities, relationships, multiplicities, interfaces), then a sequence diagram for one or two core flows, before writing the core code.
