Signals

  • A signal is a value that tells its readers when it changes. Read it by calling it: search().
  • computed derives a value from other signals. It's lazy (runs only when read) and cached (re-runs only when a dependency changed).
  • linkedSignal is a writable value that resets when its source changes.
  • effect runs side effects (save, log, call a library), not derivations.
  • Change = new value. Setting an equal value (same object, same number) stops propagation.

Cheat-sheet

    
    
      
  • State that changes→signal(initial); .set(v) or .update(old => new)
    • 
      
  • A value calculated from other state→computed(() => …), never an effect that sets a signal
    • 
      
  • Editable value that should reset when something else changes→linkedSignal({ source, computation })
    • 
      
  • Save, log, sync with localStorage or a chart library→effect(() => …)
    • 
      
  • Arrays and objects in signals→replace, don't mutate: update(list => list.filter(...))
    • 
      
  • Read a signal without depending on it→untracked(() => other())
    • 
      
  • Have an Observable, want a signal→toSignal(obs$) (HTTP page)

Added
Not in your notes. Signals arrived after Angular 16. In Angular 22 they're the core of reactivity: inputs, outputs, queries, forms and HTTP resources all speak signals, and zoneless change detection depends on them.

      
Added
Laziness, proven. CareDesk had a computed that nothing read. Its log line never appeared in any scenario: a computed that isn't read is never evaluated.

      
Added
Batched and glitch-free. Writing 'm' then 'me' in the same function produced one effect run ("me") and one recompute of each computed. Readers never see a half-updated graph.

      
Added
Equality stops the wave. Typing "ra" after "r" made filtered return a new array, but first was still the same Ravi object, so note did not reset. Default equality is Object.is; pass { equal: fn } to customise it.

    

  


  

    
Check yourself

    
Answer out loud before you open each card.

    

      
What makes computed lazy and cached?Show answer
        
It runs only when someone reads it, and it re-runs only if a signal it read last time has changed since. Otherwise it returns the cached value.

      
The search is set to the value it already has. What runs?Show answer
        
Nothing. Equal values don't notify. In the real run, only our own "set same value" log appeared.

      
Two set() calls in a row: how many effect runs?Show answer
        
One, with the final value. Effects are scheduled, not run synchronously on each write.

      
Why not effect(() => this.count.set(this.list().length))?Show answer
        
It duplicates state and runs later than the read, so the UI can briefly be inconsistent. count = computed(() => this.list().length) is always correct and needs no syncing.

      
When is linkedSignal the right tool?Show answer
        
When a value must be editable by the user but should reset (or be recalculated) when another signal changes. CareDesk's note resets whenever the patient shown changes.

      
How does a signal help change detection?Show answer
        
Templates that read a signal are registered as its consumers. When it changes, Angular schedules a refresh of exactly those views, which is what zoneless Angular relies on.
