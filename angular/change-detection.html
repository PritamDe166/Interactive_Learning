Change detection

  • Change detection = Angular re-evaluating templates and patching the DOM where values changed.
  • Angular 22 apps are zoneless: a refresh is scheduled by a signal change, a template event, an input change or markForCheck(), not by every timer or HTTP callback.
  • Components are OnPush by default: a component is skipped unless something it depends on changed.
  • An event marks its component and its ancestors; a signal refreshes only the views that read it.
  • A plain field changed in a setInterval never shows. Use a signal.

Cheat-sheet

  • Value changes but the screen doesn't→it's a plain field changed outside a template event: make it a signal
  • Data from a timer, WebSocket or third-party callback→signal.set() (or toSignal() for observables)
  • Mutated an object or array inside a signal→no refresh; replace it (update(list => [...list, p]))
  • Click handler in a deep child→that child and its ancestors are refreshed; siblings aren't
  • Legacy code that relies on "everything is checked"→changeDetection: ChangeDetectionStrategy.Eager on that component
  • Interview: "Default vs OnPush"→since v22: OnPush is the default, the old Default is called Eager

Added

Not in your notes. This page fills a gap: your notes rely on change detection (ngOnChanges, ngModel) without explaining it. It's a frequent interview topic, and the rules changed a lot between Angular 16 and 22.

Updated

zone.js is gone by default. Older apps loaded zone.js, which patched timers, promises and events to trigger a check of the whole tree after any async work. New apps are zoneless: smaller, faster, and explicit about what changed. That's why CareDesk's header clock needed a signal.

Updated

OnPush by default (v22). ChangeDetectionStrategy.OnPush is now the default and the old Default strategy is named Eager. Existing code you see in interviews may still set OnPush explicitly; it means the same thing.

Added

First render ran a second pass. In the real logs, App and PatientList were checked again right after the first render (caused by the search box's ngModel: with the box removed, the second pass disappeared). Extra passes are normal; never rely on how many times a template is evaluated.

What is change detection?Show answer

The process where Angular re-evaluates template bindings and updates the DOM where values changed. Zoneless Angular runs it when something tells it data changed: signals, template events, input changes, markForCheck.

A card button is clicked. Is the Header checked?Show answer

Not with OnPush (the default): only the card and its ancestors (PatientList, App). With Eager, yes: the Header is checked every time App is.

Why didn't the header clock update with a plain field?Show answer

Nothing told Angular: setInterval isn't a template event and there's no zone.js. Writing a signal schedules the refresh.

A signal read only in PatientCard changes. What's refreshed?Show answer

Only PatientCard. In the real run the clock tick logged a single [checked] PatientCard.

Typing in the list's search: is the card refreshed?Show answer

No. Its input (patient) is the same object and it reads no changed signals, so OnPush skips it. (Its ngDoCheck still runs, as the Lifecycle page showed.)

What did ChangeDetectionStrategy.Default become?Show answer

ChangeDetectionStrategy.Eager, and OnPush became the default, in Angular 22.
