Template-driven forms

  • In a template-driven form the template is the source of truth: ngModel on each field, #f="ngForm" on the form.
  • Angular builds a form model behind it: one control per field (keyed by name), grouped under the form.
  • Each control tracks three pairs: valid/invalid, pristine/dirty (changed?), untouched/touched (visited?).
  • Validators are HTML attributes (required, minlength), and the states appear as CSS classes (ng-invalid, ng-touched).
  • Submit with (ngSubmit) on the form, not (click) on the button.

Cheat-sheet

  • Set up→FormsModule in imports, <form #f="ngForm" (ngSubmit)="save(f)">
  • A field→name="x" [(ngModel)]="model.x" (name is required inside a form)
  • Read a field's state in the template→#x="ngModel" then x.invalid, x.touched, x.errors?.['minlength']
  • When to show an error→invalid && touched (or after a submit attempt), not on page load
  • Disable submit→[disabled]="f.invalid"
  • Clear after saving→f.resetForm({...}): values and states back to pristine/untouched

Check yourself

Answer out loud before you open each card.

Touched vs dirty?Show answer

Dirty: the user changed the value. Touched: the user focused and left the field. You can be touched but pristine (visited, didn't change), as the doctor field was after tabbing through.

Why show errors only when touched?Show answer

Every required field starts invalid. Showing red on page load scolds the user before they did anything.

What does #doctor="ngModel" give you?Show answer

A template variable pointing at that field's NgModel directive, so you can read doctor.invalid, doctor.touched, doctor.errors.

What's in f.value at submit?Show answer

An object keyed by each field's name: {"doctor":"Dr Arjun","date":"2026-11-03","reason":"ECG review"} in the real run.

After resetForm(), what are the states?Show answer

Pristine and untouched again (and invalid, since required fields are empty), so no error messages show.

When would you pick reactive forms instead?Show answer

For larger or dynamic forms, cross-field validation, or logic you want to unit-test without a template. That's the next page.
