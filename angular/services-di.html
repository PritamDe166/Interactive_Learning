Services & dependency injection

  • A service is a class for state or logic that several components share, such as CareDesk's PatientStore.
  • Components ask for it with inject(PatientStore); Angular's injector creates it and hands out the same instance.
  • New in v22: @Service(), a shorthand for @Injectable({ providedIn: 'root' }): one app-wide instance.
  • Lookups walk up the injector tree; the first provider found wins. A component's own providers make a separate instance.

Cheat-sheet

  • Shared state or logic for the whole app→@Service() class (root singleton)
  • Get a service→private readonly store = inject(PatientStore); as a field
  • One instance per component (a wizard, a dialog draft)→@Service({ autoProvided: false }) + providers: [X] on that component
  • Expose state safely→private writable signal + public asReadonly() + methods to change it
  • NG0201 "No provider found"→nothing up the tree provides it: add @Service() or a providers entry
  • NG0203 "must be called from an injection context"→move inject() to a field or the constructor

Corrected

"A service has to be injected to the root." Root is the usual choice, not a requirement. A class becomes injectable wherever it's provided: root, the app config, a route or a component. CareDesk's experiment with providers: [PatientStore] on PatientList got a second, separate instance.

Updated

ng g s now generates @Service(). In CLI 22.2, ng g s patient-store created patient-store.ts with @Service() export class PatientStore {}. @Injectable still works. Migrate with ng generate @angular/core:inject then ng generate @angular/core:service.

Updated

inject() instead of constructor parameters. Your notes inject with constructor(private loginAuth: LoginAuthService). That still works in components and @Injectable classes, but a @Service class refuses it: NG2028: @Service class cannot use constructor dependency injection. Use the `inject` function instead.

Added

Constants vs services. Your notes' export const UserLoginDetails = [...] is fine for fixed data (CareDesk's PATIENTS too). Use a service when the data changes, needs logic, or comes from an API.

Check yourself

Answer out loud before you open each card.

Header and PatientList both inject PatientStore. How many instances?Show answer

One. @Service() provides it in the root injector; the real run logged "PatientStore created #1" once, and a discharge in the list updated the header.

PatientList adds providers: [PatientStore]. What breaks?Show answer

The list gets its own instance (#2). Discharging Asha changed the list to "2 of 2" while the header, still on #1, kept saying "3 waiting".

How does Angular find a provider?Show answer

It starts at the requesting component's injector and walks up through its ancestors to the root (environment) injector. The first provider found wins. None found: NG0201.

Where can you call inject()?Show answer

In an injection context: field initialisers, the constructor, provider factories, guards and interceptors. Calling it in a click handler threw NG0203 in CareDesk.

What's the difference between @Service() and @Injectable()?Show answer

@Service() is root-provided by default and requires inject() (no constructor parameters). @Injectable() without options isn't provided anywhere until you list it in providers.

Why make the store's signal private with asReadonly()?Show answer

So components can read but not set the list directly. All changes go through methods like discharge(), which keeps rules in one place (same reasoning as encapsulation in C#).
