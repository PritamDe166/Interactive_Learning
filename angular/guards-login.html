Route guards & login flow

  • A guard is a function the router runs before entering a route: return true to continue, or a UrlTree to redirect.
  • CareDesk's authGuard sends signed-out users to /login?returnUrl=… and brings them back after sign-in.
  • An interceptor sees every HttpClient request; CareDesk's adds Authorization: Bearer ….
  • Guards are user experience, not security. Anyone can edit the browser; the server must check the token.
  • Functional guards (CanActivateFn) replaced class-based guards, which are deprecated.

Cheat-sheet

  • Protect a route→canActivate: [authGuard] on the route
  • Redirect from a guard→return router.createUrlTree(['/login'], { queryParams: { returnUrl: state.url } })
  • Generate one→ng g guard auth --functional (or pick CanActivate in the prompt)
  • Add a header to every API call→HttpInterceptorFn + provideHttpClient(withInterceptors([...]))
  • Optional query param bound to an input→it's undefined when absent: this.returnUrl() ?? '/patients'
  • "Is the guard enough security?"→no: validate the token on the server for every API call

Corrected

What was deprecated. The notes say "the CanActivate function has been deprecated" in v16. It was the class-based guard (a class implementing the CanActivate interface) that was deprecated; the canActivate route property is current, and takes functions like CareDesk's authGuard.

Corrected

Return a UrlTree instead of navigate + false. The notes' guard calls router.navigate(['login']) and returns false. Returning router.createUrlTree(...) lets the router cancel and redirect in one step, and lets you carry a returnUrl.

Corrected

The login check loop. The notes' forEach with return true doesn't stop the loop (return only exits the callback). Use some() or find(), as AuthStore.login does.

Corrected

Demo token ≠ authentication. A random token created in the browser and stored in localStorage proves nothing: in the real run, setting caredesk.token to "anything" by hand opened the patient list. Real apps get a signed token (or an HttpOnly cookie) from a server that checks credentials, and the API verifies it on every request.

Added

Input binding sets undefined. With withComponentInputBinding(), opening /login without ?returnUrl set the input to undefined, overriding its default, and navigation logged NG04018: Error parsing URL undefined. Fixed with ?? '/patients'.

Check yourself

Answer out loud before you open each card.

What can a CanActivateFn return?Show answer

true/false, a UrlTree or RedirectCommand to redirect, or an Observable/Promise of those for async checks.

Signed out, Arjun opens /patients/2. What happens?Show answer

The guard redirects to /login?returnUrl=%2Fpatients%2F2. After signing in, navigateByUrl(returnUrl) took him straight to Ravi's page.

Where does inject() work inside a guard?Show answer

Anywhere in the guard function body: the router runs guards in an injection context, so inject(AuthStore) and inject(Router) work.

Why is a client-side guard not security?Show answer

The code runs on the user's machine and can be changed or skipped. It only stops honest users from seeing pages they can't use. The API must reject requests without a valid token.

What does an interceptor do here?Show answer

It clones each outgoing request and adds Authorization: Bearer <token>. Signed out, requests went without the header; signed in, they carried Bearer demo-….

Why clone the request?Show answer

HttpRequest objects are immutable. req.clone({ setHeaders: {...} }) creates a modified copy to pass to next().
