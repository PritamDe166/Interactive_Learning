Components & templates

  • A component is a class + a template + styles, glued together by @Component.
  • Its selector (app-header) is the tag you write in another template to use it.
  • A parent must list each child it uses in imports. There are no NgModule declarations.
  • Components nest into a tree; the page you see is that tree rendered.
  • Component styles are scoped: CSS in one component doesn't leak into another.

Check yourself

    
Answer out loud before you open each card.

    

      
What three things make up a component?Show answer
        
A TypeScript class (data and behaviour), a template (HTML), and styles, connected by the @Component decorator with a selector.

      
You add <app-patient-card /> to PatientList's template. What else must you do?Show answer
        
Add PatientCard to PatientList's imports. Otherwise: NG8001: 'app-patient-card' is not a known element.

      
PatientList's CSS says h3 { color: crimson }. Is the card's name red?Show answer
        
No. The rule is scoped to PatientList's own elements. The card's h3 belongs to PatientCard. In the real build it stayed black.

      
What is :host?Show answer
        
The component's own element, e.g. <app-header>. Use it to style the wrapper, often display: block.

      
Do <app-…> tags stay in the final DOM?Show answer
        
Yes. The rendered DOM contains <app-header>, <app-patient-list> and so on, with the template's elements inside each.

      
Why keep components small?Show answer
        
Same reasons as small classes: one job each (single responsibility), easier testing, reuse (PatientCard will be used once per patient), and clearer data flow between them.
