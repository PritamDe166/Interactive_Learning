Angular 22 · Part 2 · Data flow

Parent ↔ child data flow

  • Data goes down through inputs: the card declares patient = input.required<Patient>(), the list binds [patient]="patient()".
  • Events go up through outputs: the card calls reviewed.emit(…), the list listens with (reviewed)="onReviewed($event)".
  • Two-way binding is both at once: note = model('') in the card, [(note)]="note" in the list.
  • Inputs are read-only signals: read them with patient(), derive with computed, react with effect.
  • A change means a new object. Changing a property of the same object is invisible to the child.

Cheat-sheet

    
    
      
  • Parent has data the child must show→input() in the child, [name]="value()" in the parent
    • 
      
  • Child must tell the parent something happened→output<T>() + .emit(value); parent handles (name)="fn($event)"
    • 
      
  • Child edits a value the parent owns (note, date picker, toggle)→model() + [(name)]="signal" (pass the signal, not its value)
    • 
      
  • Square brackets [x]→the right side is an expression; no brackets = a plain string
    • 
      
  • Object inside a signal changed but the child didn't update→you mutated it. Use update(p => ({ ...p, name }))
    • 
      
  • Want a value derived from an input→computed(), not effect() or ngOnChanges
    • 
      
  • Two siblings, or components far apart, share state→a service with signals (step 10), not long input/output chains

Corrected
The object trap, in today's terms. Your notes found that changing userData.name didn't fire ngOnChanges, and fixed it with {...this.userData}. The cause is reference equality: Angular compares the bound value by identity. With signals it's stricter: a signal skips notification when the new value is the same object (Object.is), so mutating does nothing downstream. In the real run the list's textbox showed "Asha Rao" while the card still said "Asha R · Cardiology".

      
Corrected
Writing to an input from the child. The notes bind [(ngModel)]="testStringfromParent" inside the child, which quietly overwrites a value the parent owns. Signal inputs are read-only (set doesn't exist on InputSignal). If the child really should change it, make it a model() so the parent hears about it, as CareDesk does with the nurse's note.

      
Updated
Why the old example still showed the new name. Under the old default change detection, every component was re-checked on every event, so the child template re-read the mutated object and looked fine even though ngOnChanges stayed silent. Since v22, components are OnPush by default (the old behaviour is now called Eager), so a child only re-renders when its inputs or signals change. More on the Change detection page.

      
Added
Signal inputs still trigger ngOnChanges. In the verified run, ngOnChanges logged patient,note first, then patient on each new object, and note after the card wrote to its model (the list's new value came back down). You rarely need it now; computed and effect cover the same cases.

      
Added
An unknown output name is a DOM event. (review) instead of (reviewed) doesn't fail as "no such output": Angular treats it as a native DOM event, so $event becomes an Event and the type check catches it. Strict templates (on by default) turn these slips into build errors.

      
Added
Decorators still work. @Input and @Output remain fully supported; the Angular docs recommend the function forms for new code. Expect both in interviews and in existing codebases.

    

  


  

    
Check yourself

    
Answer out loud before you open each card.

    

      
Which way does data flow through input() and output()?Show answer
        
Inputs carry data down from parent to child. Outputs carry events up from child to parent. Think from the child's point of view: what comes in, what goes out.

      
PatientList runs this.patient().name = 'Asha Rao'. What does the card show?Show answer
        
The old heading. The signal still holds the same object, so nothing is notified; computed and effect don't re-run and the OnPush card isn't refreshed. Replace the object: patient.update(p => ({ ...p, name: 'Asha Rao' })).

      
What does [(note)]="note" expand to?Show answer
        
[note]="note()" (noteChange)="note.set($event)". model() creates the noteChange output for you. Pass the signal itself; [(note)]="note()" fails with NG5002.

      
Can the card call this.patient.set(…) on its input?Show answer
        
No: Property 'set' does not exist on type 'InputSignal<Patient>'. Inputs are read-only. Use model() for a value the child may change, or emit an event and let the parent change it.

      
What's the difference between patient="patient()" and [patient]="patient()"?Show answer
        
Without brackets the child receives the literal string "patient()". With brackets Angular evaluates the expression and passes the Patient object.

      
When should you reach for a service instead of inputs and outputs?Show answer
        
When components aren't parent and child (siblings, distant parts of the tree), or when you'd pass the same value through several layers just to reach one child. CareDesk moves its patients into a service on step 10.
