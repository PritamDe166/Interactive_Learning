Lifecycle hooks

  • Angular calls hook methods on a component at fixed moments: created, inputs changed, checked, destroyed.
  • ngOnInit = inputs are ready, start work. ngOnDestroy = clean up (timers, subscriptions).
  • The …Checked hooks and ngDoCheck run on every check, so keep them cheap.
  • ngOnChanges runs only for bound inputs, before ngOnInit and again on each new value.
  • The constructor isn't a hook: it runs before inputs exist. Reading a required input there fails the build.

Cheat-sheet

  • Need an input's value to start something→ngOnInit (or a computed / effect)
  • Started a timer, listener or subscription→stop it in ngOnDestroy or inject(DestroyRef).onDestroy(…)
  • Need the rendered DOM (measure, focus, chart library)→afterNextRender(() => …)
  • Need to react to an input changing→computed / effect first; ngOnChanges if you need previous values
  • Heavy work in ngDoCheck / …Checked→move it out: these run on every check, even when nothing changed
  • Component disappears and comes back (@if, routing)→it's a new instance: constructor and ngOnInit run again, state resets

Check yourself

Answer out loud before you open each card.

Constructor or ngOnInit: where do you read an input?Show answer

ngOnInit (or a computed). Inputs aren't set when the constructor runs; for a required signal input Angular even fails the build (NG8118).

The list gives the card a new patient object. Does ngOnInit run again?Show answer

No. The same instance gets ngOnChanges: patient and a check. ngOnInit runs once per instance.

The user types in the list's search box. Which card hooks run?Show answer

ngDoCheck, ngAfterContentChecked, ngAfterViewChecked, afterEveryRender. Nothing about the card changed, yet its check hooks ran.

What happens to a setInterval you never clear?Show answer

It keeps running after the component is destroyed, holding the component in memory (a leak). Clear it in ngOnDestroy or with DestroyRef.

Discharge, then admit again. Is the waiting clock back at 0?Show answer

Yes. @if destroyed the old card and created a new instance: constructor, ngOnChanges, ngOnInit all ran again.

Where do you put code that measures an element's size?Show answer

afterNextRender (once) or afterEveryRender. They run after the DOM is updated, and only in the browser (not during server rendering).
