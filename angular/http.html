HTTP, resource & RxJS basics

  • httpResource(() => url) fetches data and exposes signals: isLoading(), hasValue(), value(), error().
  • The URL function is reactive: when its signals change the request re-runs; returning undefined means "don't fetch".
  • HttpClient methods return an Observable: nothing is sent until you subscribe, and each subscription sends again.
  • RxJS operators go in pipe(): map, tap, catchError…
  • Rule of thumb: reads → httpResource; writes (POST, PUT, DELETE) → HttpClient.

Added
value() throws in the error state. CareDesk's first version used res.value() ?? []. When the server returned 500 the console showed ResourceValueError: Resource is currently in an error state (see Error.cause for details): Http failure response for …/api/patients.json: 500 Internal Server Error. Guard with hasValue().

      
Added
Fetching too early. The first version also requested patients on the login page, without a token, because the header injects the store at start-up. Making the URL depend on isLoggedIn() removed that request and made the list load by itself right after sign-in.

      
Added
About the API. CareDesk reads public/api/patients.json, a static sample file served by ng serve. The POST to /api/appointments was answered by the test script with 201; a real backend (an ASP.NET Core minimal API, say) would validate the bearer token there.

    

  


  

    
Check yourself

    
Answer out loud before you open each card.

    

      
What signals does httpResource give you?Show answer
        
value(), hasValue(), isLoading(), error() and status(), plus reload(). The template reads them like any signal.

      
How do you stop a resource from fetching?Show answer
        
Return undefined from the URL function. CareDesk does that while signed out; no request was sent on the login page.

      
http.get(url) without subscribe: request or not?Show answer
        
No request. HttpClient Observables are cold: they run when subscribed, and each subscription runs again (two subscribes = two GETs in the real run).

      
What does pipe(map(...)) do?Show answer
        
Transforms each emitted value. In the real run, mapping the patient list to urgent names emitted ["Asha","Kiran"] from one GET.

      
Why keep a linkedSignal copy of the server list?Show answer
        
So the UI can change it locally (discharge, admit) while still resetting automatically whenever the resource loads new data.

      
Promise or Observable for HTTP?Show answer
        
HttpClient uses Observables: lazy, cancellable, composable with operators, and able to emit progress events. For simple reads in new code, httpResource hides that and gives signals.
