EC2 instance storage: review

  • EBS is the network disk of one instance in one AZ; snapshots back it up and move it.
  • AMIs are launch templates built on snapshots; EC2 Image Builder automates them.
  • Instance store is the fastest disk but disappears on stop/terminate.
  • Shared file storage: EFS (Linux), FSx for Windows (SMB/AD), FSx for Lustre (HPC).

Section summary

EBS volumes

  • Network drive, one instance at a time, one AZ.
  • Persistent; provision GiB and IOPS, billed even unattached.
  • Delete on termination: root Yes, extra No.
  • gp3/gp2 general · io2/io1 IOPS · st1/sc1 HDD.

Snapshots

  • Incremental backup of a volume, Region-level.
  • Restore in any AZ; copy to another Region.
  • Archive tier: up to 75% cheaper, 24–72 h restore.
  • Recycle Bin rule recovers deleted snapshots/AMIs.

AMIs & Image Builder

  • AMI = template: OS, software, config (snapshots + metadata).
  • Public, custom, Marketplace; Region-scoped, copyable.
  • Custom AMI → faster boot. Immutable.
  • Image Builder: build → test → distribute; free service.

Instance store

  • Disk on the physical host; highest IOPS.
  • Lost on stop, terminate, hardware failure; survives reboot.
  • Cache, buffers, scratch; backups are yours.

EFS

  • Managed NFS, Linux only, hundreds of instances, multi-AZ.
  • Pay per use, ~3× gp2 price.
  • Lifecycle → EFS-IA (up to 95% cheaper) / Archive.

FSx & responsibility

  • FSx for Windows: SMB, NTFS, AD, Multi-AZ. FSx for Lustre: HPC, S3-linked.
  • AWS: infrastructure, replication, hardware. You: backups, encryption, data, instance store risk.

Section cheat-sheet

  • Persistent disk for one instance→EBS
  • EBS data to another AZ→Snapshot → create volume there
  • Backup for DR in another Region→Copy snapshot / copy AMI
  • Cheapest long-term snapshot storage→EBS Snapshot Archive
  • Undo accidental snapshot/AMI deletion→Recycle Bin
  • Faster, consistent launches→Custom AMI
  • Automate AMI patching and testing→EC2 Image Builder
  • Highest I/O, temporary data→Instance store
  • Shared Linux files across AZs→EFS (+ EFS-IA)
  • Windows SMB share with AD→FSx for Windows File Server
  • High performance computing→FSx for Lustre
