AWS CLF-C02 / ELB & Auto Scaling / Section review

ELB & Auto Scaling: review

  • Vertical scaling = bigger instance; horizontal = more instances; elasticity = more or fewer automatically; high availability = 2+ AZs.
  • A load balancer gives one DNS name, spreads requests across AZs, health-checks targets and can end HTTPS.
  • An Auto Scaling group keeps between min and max instances, launches them from a launch template, replaces unhealthy ones and registers them with the load balancer.
  • Scaling policies decide when: simple, step, target tracking, scheduled or predictive.

Section summary

HA, scalability, elasticity

  • Vertical: bigger instance (scale up), has a ceiling.
  • Horizontal: more instances (scale out), needs a stateless app.
  • Elasticity: automatic scale out and in, pay for what you use.
  • High availability: at least 2 AZs. Agility: resources in minutes (a distractor).

Elastic Load Balancing

  • Managed; one DNS name; spreads load across AZs.
  • Health checks stop traffic to broken instances.
  • TLS termination with ACM; instances allow traffic only from the load balancer's security group.
  • ALB layer 7 (HTTP, path/host routing, Lambda). NLB layer 4 (TCP/UDP, static IP, extreme performance). GWLB layer 3 (firewall appliances). Classic: previous generation.

Auto Scaling groups

  • Min, desired, max; launch template = what to launch.
  • Registers new instances with the target group; deregisters before removing.
  • Replaces unhealthy instances (turn on ELB health checks for app failures).
  • Multi-AZ; free, you pay for the instances.

Scaling strategies

  • Simple: alarm → fixed change, then cooldown. Step: change sized by the breach.
  • Target tracking: keep a metric (CPU 50%) steady. Recommended first.
  • Scheduled: known times. Predictive: machine-learning forecast, scales ahead.

Commonly confused pairs

PairThe difference
Vertical vs horizontal scalingA bigger instance vs more instances
Scalability vs elasticityCan handle more load vs adjusts capacity automatically, both ways, with demand
Elasticity vs agilityCapacity follows demand vs resources are available in minutes
High availability vs scalabilitySurvives a data-centre failure (2+ AZs) vs handles more load
Load balancer vs Auto Scaling groupRoutes each request to a healthy instance vs decides how many instances exist and replaces broken ones
ALB vs NLBLayer 7 HTTP with smart routing and a DNS name vs layer 4 TCP/UDP, extreme performance and a static IP
NLB vs GWLBForwards traffic to your app vs passes traffic through security appliances first
EC2 vs ELB health checks in an ASGInstance and hardware problems only vs also replaces instances whose app fails the load balancer's check
Simple vs step scalingOne fixed change then a cooldown vs a change sized by how far the alarm is breached
Scheduled vs predictive scalingTimes you set vs times machine learning forecasts

Section cheat-sheet

  • Bigger instance→Vertical scaling
  • More instances→Horizontal scaling
  • Automatically match capacity to demand→Elasticity: Auto Scaling group
  • Survive an AZ failure→Multi-AZ load balancer + ASG
  • HTTP path or host routing, Lambda targets→ALB
  • TCP/UDP, static IP, millions of requests→NLB
  • Third-party firewall appliances→GWLB
  • Replace failed instances automatically→ASG
  • Keep CPU at 50%→Target tracking
  • Known event at a known time→Scheduled scaling
  • Forecast with machine learning→Predictive scaling
  • Resources in minutes instead of weeks→Agility
Questions are original, written to the official exam guide (Domain 1 cloud concepts and Domain 3 Task 3.3 compute) and the scenario patterns of public practice sets: AWS CLF-C02 exam guide, What is Elastic Load Balancing?, What is Amazon EC2 Auto Scaling?. Section notes: ELB and ASG notes 1 to 8.
