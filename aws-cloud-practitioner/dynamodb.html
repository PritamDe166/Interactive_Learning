Amazon DynamoDB & DAX

  • DynamoDB is a serverless, fully managed NoSQL key-value and document database with single-digit millisecond latency at any scale.
  • You define only the primary key (partition key, optional sort key); items can have different attributes. No JOINs.
  • Capacity is on-demand or provisioned; data is replicated across 3 AZs.
  • DAX is an in-memory cache for DynamoDB only, with microsecond reads.

Points to remember

  1. DynamoDB = serverless, fully managed NoSQL (key-value and document); single-digit ms at any scale.
  2. Table → items → attributes; max item size 400 KB; items can differ (flexible schema).
  3. Primary key = partition key (+ optional sort key). Query by key is fast; other lookups need a scan or a secondary index.
  4. No JOINs or relational features.
  5. Capacity: on-demand (pay per request) or provisioned (+ auto scaling). Table classes: Standard, Standard-IA.
  6. Replicated across 3 AZs; access controlled with IAM.
  7. DAX: DynamoDB Accelerator, in-memory cache, microsecond reads, DynamoDB only.

Create a table and add items (outline)
  1. DynamoDB → Create table: name Visits, partition key patientId (String), sort key visitDate (String). Default settings use on-demand capacity.
  2. Explore items → Create item: add attributes; create a second item with different attributes.
  3. Run a Query on one patientId, then a Scan with a filter, and compare items read.
  4. Delete the table.

Cheat-sheet

  • Serverless NoSQL, single-digit ms→DynamoDB
  • Key-value at massive scale→DynamoDB
  • Microsecond cache for DynamoDB→DAX
  • Need JOINs→Not DynamoDB: RDS/Aurora
  • Pay per request, unpredictable traffic→On-demand capacity
  • Rarely read table, cheaper storage→Standard-IA table class
  • Multi-Region active-active→Global tables

DynamoDB vs DocumentDB. Both store JSON-like data. DynamoDB is AWS's own serverless key-value database; DocumentDB is for MongoDB-compatible workloads.
