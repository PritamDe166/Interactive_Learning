Choosing EC2 storage

  • Two questions pick the answer: is it shared by many instances? and what kind of workload?
  • One instance: EBS (persistent) or instance store (fastest, temporary).
  • Shared: EFS (Linux), FSx for Windows (SMB/AD), FSx for Lustre (HPC).
  • Shared responsibility: AWS runs and replicates the storage; you own backups, encryption and your data.

Points to remember

  1. EBS: network drive, one instance, one AZ, persistent; snapshots back it up or move it.
  2. Instance store: hardware disk on the host, highest I/O, lost on stop/terminate.
  3. EFS: managed NFS for Linux, shared by hundreds of instances across AZs, pay per use; EFS-IA/Archive for cold files.
  4. FSx for Windows File Server: SMB/NTFS share with Active Directory.
  5. FSx for Lustre: Linux file system for HPC, can be backed by S3.
  6. AMI is not storage you mount: it's the launch template (built on snapshots); EC2 Image Builder automates it.
  7. S3 is object storage used with EC2 (backups, static files), not a disk the OS mounts. Its own section comes later.
  8. Shared responsibility: AWS = infrastructure, replication of EBS/EFS data, replacing faulty hardware, keeping its staff out of your data. You = backup/snapshot procedures, encryption, the data itself, and understanding the risk of instance store.

  • Making sure AWS employees can't access your data

You

  • Setting up backup / snapshot procedures
  • Setting up data encryption
  • Whatever data you put on the drives
  • Understanding the risk of using instance store

Cheat-sheet

  • One instance, persistent→EBS
  • One instance, fastest, disposable→Instance store
  • Shared, Linux, general→EFS
  • Shared, Windows / SMB / AD→FSx for Windows File Server
  • Shared, HPC / ML→FSx for Lustre
  • Template to launch servers→AMI
