Amazon RDS & Aurora

  • RDS is a managed relational database: MySQL, PostgreSQL, MariaDB, Oracle, SQL Server, Db2.
  • AWS patches, backs up and monitors it; you can't SSH in. Point-in-time restore is built in.
  • Aurora is AWS's cloud-native MySQL/PostgreSQL-compatible engine: faster, with storage copied 6 ways across 3 AZs.
  • Aurora Serverless scales capacity automatically and bills per second.

Aurora cluster volumeA SAN shared by the primary and its replicasSpread across 3 AZs and grows by itself.

Points to remember

  1. RDS engines: MySQL, PostgreSQL, MariaDB, Oracle, SQL Server, Db2 (plus Aurora).
  2. Managed: provisioning, OS and engine patching, automated backups with point-in-time restore, monitoring, storage autoscaling. No SSH.
  3. Aurora: MySQL- and PostgreSQL-compatible, cloud-native, higher performance; storage auto-grows (up to 256 TiB), 6 copies across 3 AZs; up to 15 replicas.
  4. Aurora Serverless: automatic capacity scaling, per-second billing; for unpredictable or intermittent workloads.
  5. Snapshots: restore creates a new DB; copy across Regions for DR; share with other accounts.
  6. Cost: per instance-hour plus storage; Reserved Instances for steady workloads.
  7. Credentials: password, IAM database authentication, or AWS Secrets Manager.

In the console

Create an RDS database (outline)
  1. RDS → Create database → Standard create → engine MySQL (or another).
  2. Template Free tier or Dev/Test (Single-AZ); Production enables Multi-AZ options.
  3. Set the identifier, admin user and password (or let Secrets Manager manage it), instance class db.t4g.micro, 20 GB gp3 storage.
  4. Connectivity: choose the VPC and security group; public access only for a quick test.
  5. After it is Available, connect with a client to the endpoint, then try Actions → Take snapshot and Restore.
  6. Delete the database when done (choose whether to keep a final snapshot).

Cheat-sheet

  • Managed relational database, automated backups→RDS
  • SQL Server or Oracle, managed→RDS
  • Cloud-native MySQL/PostgreSQL, best performance→Aurora
  • Relational, unpredictable load, no capacity planning→Aurora Serverless
  • Restore a snapshot→Creates a new database
  • DR copy in another Region→Copy the snapshot cross-Region
  • SSH into RDS→Not possible

RDSAurora
EnginesMySQL, PostgreSQL, MariaDB, Oracle, SQL Server, Db2MySQL- and PostgreSQL-compatible

Read replicasYes (limit depends on engine)Up to 15, share storage
ServerlessNoAurora Serverless
PerformanceStandard engineAWS quotes several times higher throughput

Performance figures move. Older material says Aurora is "5x MySQL and 3x PostgreSQL"; AWS's current page claims more. Remember "faster than the standard engines", not the multiplier.

Aurora Global Database replicates an Aurora cluster to other Regions with typically under a second of lag, for global reads and DR.

RDS Proxy pools database connections for apps with many short connections, such as Lambda functions.
