DynamoDB Global Tables

  • A global table keeps a replica of a DynamoDB table in several Regions.
  • Every replica takes reads and writes: active-active (multi-active).
  • Users get low latency locally, and the table survives a Region problem.
  • Concurrent updates resolve as last writer wins by default.

In terms you know

AWSClosest thing you knowThe difference
Global tableSQL Server merge or peer-to-peer replication between officesFully managed by DynamoDB, typically under a second between Regions.

Points to remember

  1. Global tables = multi-Region, multi-active replication of a DynamoDB table.
  2. Any replica serves reads and writes; changes replicate asynchronously (typically within a second).
  3. Use for low latency worldwide and Region-level resilience.
  4. Conflicts: last writer wins by default; a multi-Region strong consistency mode also exists.
  5. Compare: an RDS cross-Region read replica is read-only; writes go to one primary.

Cheat-sheet

  • Active-active NoSQL across Regions→DynamoDB global tables
  • Low-latency writes for users worldwide→Global tables
  • Conflict rule→Last writer wins
  • Read-only copy of a relational DB in another Region→RDS cross-Region read replica
