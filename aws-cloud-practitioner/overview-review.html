Cloud & AWS overview: review

  • Traditional IT means owning every box on the request path; cloud computing rents it on demand.
  • The service model decides how much of the stack you manage: IaaS, PaaS, SaaS.
  • AWS runs in Regions made of Availability Zones, plus edge locations near users.
  • Security is split: AWS secures the cloud, you secure what you put in it.

Section summary

Everything from the five topics on one screen. Read it before the questions.

Traditional IT

  • A server = CPU, RAM, storage (+ database, network).
  • Browser asks DNS for the IP, then internet → router → switch → server.
  • Owning it means rent, power, cooling, staff 24/7, slow growth, and one site that can fail.

Cloud computing

  • On-demand IT over the internet, pay as you go.
  • 5 characteristics: on-demand self-service, broad network access, resource pooling, rapid elasticity, measured service.
  • 6 advantages: CAPEX→OPEX, economies of scale, stop guessing capacity, speed & agility, no data centres to run, global in minutes.
  • Deployment: private, public, hybrid.

IaaS, PaaS, SaaS & pricing

  • IaaS (EC2): you manage OS and up. PaaS (Elastic Beanstalk): code and data. SaaS: use the app.
  • Data, users and access settings are always yours.
  • You pay for compute, storage and data transfer out; data in is generally free.

Regions, AZs & edge

  • Region = geographic area; most services are regional.
  • Each Region has ≥ 3 AZs; an AZ = one or more isolated data centres.
  • Multi-AZ = high availability. Edge locations cache content near users (CloudFront).
  • Pick a Region by compliance, latency, service availability, price.
  • Global services: IAM, Route 53, CloudFront, WAF.

Shared responsibility

  • AWS: security of the cloud (facilities, hardware, network, hypervisor).
  • You: security in the cloud (data, IAM, security groups, guest OS on EC2, encryption).
  • The split shifts by service: on RDS and Lambda AWS also patches the OS/runtime.
  • Shared controls: patching, configuration management, awareness & training.

Section cheat-sheet

  • Upfront hardware → monthly bill→CAPEX → OPEX
  • Capacity follows demand automatically→Elasticity
  • Choose and patch the OS yourself→IaaS (EC2)
  • Just upload code→PaaS (Elastic Beanstalk)
  • Some workloads on-premises, some on AWS→Hybrid cloud
  • Survive a data-centre failure→Multiple Availability Zones
  • Data must stay in a country→Pick that Region (compliance first)
  • Cache near users→Edge locations (CloudFront)
  • Physical security, hypervisor→AWS (security OF the cloud)
  • Data, IAM, security groups, guest OS on EC2→You (security IN the cloud)
  • Data transfer into AWS→Generally free; data out is charged
