AWS CLF-C02 / Databases & analytics / Section review

Databases & analytics: review

  • Relational: RDS (six engines) and Aurora (cloud-native, Serverless). Multi-AZ for HA, read replicas for reads.
  • NoSQL: DynamoDB (serverless key-value, DAX, global tables), DocumentDB (MongoDB), Neptune (graph).
  • In-memory: ElastiCache. Other: Timestream (time series), Managed Blockchain.
  • Analytics: Redshift (warehouse), Athena (SQL on S3), EMR (Spark/Hadoop), Glue (ETL), QuickSight (dashboards). Migration: DMS (+ SCT).

Section summary

Relational

  • RDS: managed MySQL, PostgreSQL, MariaDB, Oracle, SQL Server, Db2; no SSH; backups with point-in-time restore.
  • Aurora: MySQL/PostgreSQL-compatible, 6 copies in 3 AZs, auto-growing storage, Serverless option.
  • Multi-AZ = sync standby, automatic failover. Read replica = async, reads, manual promotion.

NoSQL & in-memory

  • DynamoDB: serverless key-value, single-digit ms, partition/sort key, no JOINs; on-demand or provisioned.
  • DAX: microsecond cache for DynamoDB only. Global tables: multi-Region active-active.
  • ElastiCache: Valkey / Redis OSS / Memcached cache for any DB.
  • DocumentDB = MongoDB; Neptune = graph; Timestream = time series.

Analytics

  • Redshift: columnar MPP data warehouse (OLAP); Serverless option.
  • Athena: serverless SQL on S3, $5 per TB scanned; Parquet + partitions cut cost.
  • EMR: managed Spark/Hadoop clusters, Spot task nodes.
  • Glue: serverless ETL + Data Catalog. QuickSight: BI dashboards.

Migration & responsibility

  • DMS: migrate with the source online, ongoing change replication.
  • SCT converts schemas between different engines.
  • Managed DB: AWS patches OS and engine; you own data, schema, access and settings.
