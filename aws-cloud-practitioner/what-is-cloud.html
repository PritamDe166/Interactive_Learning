What is cloud computing

  • Cloud computing = on-demand delivery of compute, storage, databases and other IT resources over the internet, with pay-as-you-go pricing.
  • The provider (AWS) owns and runs the hardware; you ask for what you need through a website or API and get it in minutes.
  • Five characteristics: on-demand self-service, broad network access, resource pooling, rapid elasticity, measured service.
  • Three deployment models: private, public (AWS) and hybrid (some on-premises, some in the cloud).

Points to remember

  1. Cloud computing = on-demand delivery of compute, storage, databases and other IT over the internet, with pay-as-you-go pricing.
  2. The provider owns and runs the hardware; you provision through a web console or API in minutes.
  3. Five characteristics: on-demand self-service, broad network access, resource pooling (multi-tenancy), rapid elasticity and scalability, measured service.
  4. Six advantages (quoted on the exam): trade CAPEX for OPEX, economies of scale, stop guessing capacity, speed and agility, stop spending money running data centres, go global in minutes.
  5. Deployment models: private (one organisation), public (AWS, shared over the internet), hybrid (some on-premises, some cloud, connected).
  6. Elasticity = scale up and down automatically with demand; scalability = able to handle more load.
  7. Cloud also makes high availability and fault tolerance easier by spreading across data centres.

Exam cheat-sheet

  • Get resources yourself, no ticket to a vendor→On-demand self-service
  • Reachable over the network from many device types→Broad network access
  • Many customers share the same physical hardware, isolated→Resource pooling · multi-tenancy
  • Grow and shrink quickly with demand→Rapid elasticity
  • Usage is metered; pay for what you used→Measured service
  • Upfront hardware purchase becomes a monthly bill→CAPEX → OPEX (trade fixed for variable expense)
  • Keep some servers on-premises, extend into AWS→Hybrid cloud

1 · Trade CAPEX for OPEX

Pay monthly for what you use instead of buying hardware up front.

2 · Economies of scale

AWS buys at huge scale, so usage prices are lower than you could get alone.

3 · Stop guessing capacity

Scale with measured demand instead of forecasting years ahead.

4 · Speed and agility

New resources in minutes, so trying things is cheap.

5 · Stop running data centres

No racking, power or cooling; spend effort on your app.

6 · Go global in minutes

Deploy close to users in Regions around the world.

Added

The problems cloud computing solves are the ones from the previous topic: no data-centre rent, power or cooling to pay, no weeks of waiting for hardware, capacity that follows demand, and AWS's team (not yours) replacing failed hardware. Cloud also makes high availability and fault tolerance easier, because you can spread an app across several data centres.

Added

Everyday examples from the course: Gmail (email), Dropbox and Google Drive (storage), Netflix (built on AWS) and Google Photos. You use cloud services daily without thinking about the servers behind them.

Many customers' virtual machines run on the same physical server, isolated from each other. Which characteristic?Show answer

Resource pooling (multi-tenancy). It is also why economies of scale work.

"Elasticity" vs "scalability": what's the difference?Show answer

Scalability is being able to handle more load by adding resources. Elasticity is doing that automatically, up and down, to match demand so you don't pay for idle capacity.

A bank keeps its core ledger in its own data centre and runs its mobile app's backend on AWS. Which model?Show answer

Hybrid cloud.

"We no longer have to buy servers for next year's growth." Which advantage?Show answer

Stop guessing capacity. (If the sentence stresses the upfront money instead, the answer is "trade CAPEX for OPEX".)

Who owns and maintains the hardware in the public cloud?Show answer

The cloud provider (AWS). You use it through a web console or API.
