AWS Budgets & billing alerts

  • Before launching anything, create a budget so AWS emails you when spending crosses a threshold.
  • IAM users can't see billing until the root user activates IAM access to billing (a root-only task).
  • The Bills page shows charges by service; the Free Tier page shows usage against free limits.
  • EC2 costs are not just the instance: EBS volumes, Elastic IPs, NAT Gateways, load balancers and snapshots bill too.

Points to remember

  1. AWS Budgets tracks cost or usage and sends alerts by email (or SNS) when actual or forecasted spend crosses a threshold.
  2. Zero-spend budget: alerts as soon as you spend anything. Monthly cost budget: e.g. $10 with alerts at 85% and 100% actual, and 100% forecasted.
  3. IAM users see Access denied in Billing until the root user enables "IAM user and role access to Billing information" (Account page). They still need IAM permissions.
  4. Bills → Charges by service tells you what caused a charge. Free Tier shows current and forecasted usage against free limits.
  5. "Free Tier" doesn't mean everything is free. Common EC2-related surprises: NAT Gateway, public IPv4 / Elastic IP, EBS volumes and snapshots, load balancers.
  6. Stopping an instance stops compute charges, but EBS keeps billing. Terminate and delete when done.
  7. Resources are regional: check every Region you used when hunting a charge.
  8. Budgets alert; they don't stop resources by themselves (unless you configure budget actions).

In the console

Set up billing access and two budgets (from the course hands-on)
  1. Sign in as root → account menu → Account → IAM user and role access to Billing information → Edit → Activate IAM access. Sign out of root.
  2. As your IAM admin user open Billing and Cost Management: month-to-date cost, forecast, last month.
  3. Bills → pick a month → Charges by service → expand EC2 to see instance, EBS, Elastic IP, NAT Gateway lines.
  4. Free Tier: check current vs forecasted usage.
  5. Budgets → Create budget → Use a template → Zero spend budget, enter your email.
  6. Create another: Monthly cost budget, amount 10 USD, email; alerts at 85% and 100% actual, 100% forecasted.
  7. When an alert email arrives: Bills → charges by service → find the resource → stop or delete it, in every Region.

Exam cheat-sheet

  • Alert when cost or usage passes a threshold→AWS Budgets
  • Alert before the month ends, based on trend→Forecasted budget alert
  • IAM admin gets Access denied on Billing→Root must activate IAM billing access
  • Which service caused this charge?→Bills → charges by service

Check yourself

An IAM user with AdministratorAccess can't open the Billing console. Why?Show answer

IAM access to billing hasn't been activated by the root user. It's a root-only setting.

Your instance is stopped. Can you still be charged?Show answer

Yes: its EBS volumes (and any Elastic IP) keep billing.

What's the difference between an actual and a forecasted alert?Show answer

Actual fires when real spend crosses the threshold; forecasted fires when AWS predicts you will cross it by month end.
