EC2 basics

  • Amazon EC2 (Elastic Compute Cloud) rents you virtual servers called instances. It is IaaS: AWS runs the hardware, you run the OS and up.
  • Every launch makes the same choices: AMI (OS image), instance type (CPU, RAM), storage (EBS), key pair, security group (firewall) and optional user data.
  • A visitor's request reaches the instance's public IP, passes the security group, and is answered by the software on the instance.
  • EC2 comes with friends: EBS volumes, Elastic Load Balancers and Auto Scaling groups (later sections).

Points to remember

  1. EC2 = Elastic Compute Cloud, virtual servers on demand: IaaS.
  2. Launch choices: AMI (OS: Linux, Windows, macOS), instance type (vCPU, RAM, network), storage (EBS/EFS network drives or instance store), networking (public/private IP), security group, key pair, user data.
  3. Security group = the instance's firewall. Inbound blocked by default; open 22 for SSH, 80/443 for web, 3389 for RDP.
  4. User data = bootstrap script that runs once, at first launch, as root.
  5. Public IPv4 reaches the instance from the internet and changes after stop/start; the private IP is for inside AWS and stays.
  6. Stop = no compute charge, EBS kept. Terminate = gone for good (root volume deleted by default).
  7. Shared responsibility for EC2: AWS secures the infrastructure, host isolation and hardware; you handle security group rules, OS patches, installed software, IAM roles and data.
  8. EC2 is regional; an instance lives in one Availability Zone.

In the console

Launch "My First Instance" (from the course hands-on)
  1. EC2 → Instances → Launch instances; name it My First Instance.
  2. AMI: Amazon Linux (64-bit x86). Type: a free-tier eligible size (t2.micro or t3.micro, depending on Region and account).
  3. Key pair: create EC2 Tutorial, RSA, .pem (or .ppk for PuTTY). Download it; AWS can't show it again.
  4. Network: keep defaults (public IP on). Security group: allow SSH 22 and HTTP 80. (In real life restrict SSH to your IP.)
  5. Storage: 8 GiB General Purpose SSD, delete on termination = yes.
  6. Advanced details → User data: paste the script that installs httpd and writes a Hello World page.
  7. Launch, wait for Running, open http://<public IPv4> (not https). Give user data a minute or two.
  8. Stop, start (note the new public IP), and terminate when done.
