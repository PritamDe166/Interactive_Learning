AWS CLF-C02 / Amazon S3 / 3 · Domain 3 Technology

S3 Static Website Hosting

  • S3 can serve a static website (HTML, CSS, JavaScript, images) with no web server.
  • Enable static website hosting, set an index document, and make the objects publicly readable.
  • 403 Forbidden means the content isn't public yet.
  • The website endpoint is HTTP only; use CloudFront for HTTPS and a custom domain.

Points to remember

  1. S3 hosts static content only: no server-side code.
  2. Steps: enable Static website hosting, set the index document (and an error document), upload the files, make them public.
  3. Public = Block Public Access off + a bucket policy allowing s3:GetObject to *.
  4. Website URL format: http://<bucket>.s3-website-<region>.amazonaws.com or …s3-website.<region>…, depending on the Region.
  5. 403 Forbidden = not public yet. 404 = the object doesn't exist.
  6. The website endpoint is HTTP only; put CloudFront in front for HTTPS, caching and a custom domain.

In the console

Host a static site (outline)
  1. Create a bucket (its name can match your domain if you will use one) and upload index.html and an image.
  2. Properties → Static website hosting → Enable, index document index.html.
  3. Open the Bucket website endpoint URL: 403 Forbidden.
  4. Permissions: turn off Block Public Access and add a public-read bucket policy. Reload: the page appears.

Cheat-sheet

  • Cheapest way to host a static website→S3 static website hosting
  • 403 Forbidden on the website endpoint→Not public: BPA or policy
  • HTTPS for an S3 website→CloudFront
  • Server-side code per request→Not S3: use compute
  • Page shown for missing paths→Error document
  • Page shown for /→Index document

Reference

ResponseUsual cause
200 OKHosting on, object exists, content public
403 ForbiddenBlock Public Access on or no public bucket policy
404 Not FoundObject (or index document) doesn't exist
404 NoSuchWebsiteConfigurationStatic website hosting not enabled
No HTTPSThe website endpoint is HTTP only

REST endpoint vs website endpoint. The normal bucket URL (bucket.s3.region.amazonaws.com) supports HTTPS but doesn't serve index documents or redirects. The website endpoint does, but only over HTTP.

CloudFront with a private bucket. With CloudFront and origin access control (OAC), the bucket can stay private: only CloudFront may read it. This is the recommended setup.

You enabled website hosting and uploaded index.html, but visitors get 403. What is missing?Show answer

Public access: turn off Block Public Access and add a public-read bucket policy.

Can S3 run a PHP or ASP.NET page?Show answer

No. S3 serves static files only.

How do you serve the S3 site over HTTPS?Show answer

Put Amazon CloudFront in front of it.

Which file does S3 return for the root /?Show answer

The index document, usually index.html.

Is a static website on S3 serverless?Show answer

Yes. There is no server to manage; you pay for storage and requests.

What makes CloudFront useful even without HTTPS?Show answer

It caches content at edge locations close to users, so the site loads faster.
