Traditional IT: how a website is served

  • A server is a computer with CPU (compute), RAM (memory) and storage, usually backed by a database.
  • To open a website, the browser asks DNS for the server's IP address, then the request travels the internet → router → switch → server.
  • In traditional IT you buy, rack, power, cool and staff every one of those boxes yourself.
  • Its limits (big upfront cost, slow to grow, one failure takes you down) are why cloud computing exists.

Points to remember

  1. A server = CPU (compute) + RAM (memory) + storage; data usually lives in a database.
  2. Computers find each other by IP address. DNS turns a name like caredesk.test into an IP.
  3. A router connects networks (your data centre to the internet); a switch connects machines inside one network.
  4. A request goes browser → DNS → internet → router → switch → server → database, and the answer comes back the same way.
  5. Traditional IT means you own every box: rent, power, cooling, maintenance, hardware replacement and a team on call 24/7.
  6. Capacity is fixed by what you bought; new servers take weeks. You either turn users away at peaks or pay for idle machines.
  7. Everything in one place means one disaster (power cut, fire, flood) takes the whole site down.
  8. These problems are exactly what cloud computing answers (next topic).

Cheat-sheet

  • Name → IP address→DNS
  • Connects your network to other networks (the internet)→Router
  • Connects machines inside one network→Switch
  • Does the work, holds data while working, keeps data→CPU · RAM · storage
  • Buy hardware up front, wait weeks, guess capacity→Traditional IT (the problem the cloud solves)

Reference

Part of a serverWhat it does
Compute (CPU)Runs the code: works out the answer to each request.
Memory (RAM)Fast, temporary working space while the code runs.
StorageKeeps files and data after the power goes off.
DatabaseStores data in a structured way so it can be searched and updated.
NetworkRouters, switches and DNS servers that let machines find and reach each other.
Network termMeaning
ClientThe machine that asks (a browser, a phone app).
ServerThe machine that answers.
IP addressThe number used to reach a machine on a network, such as 203.0.113.10.
DNSThe phone book that turns a name (caredesk.test) into an IP address.
RouterMoves traffic between networks, such as from the internet into your office network.
SwitchMoves traffic between machines on the same network.

The problems with running it yourself: you pay rent for the data centre, power, cooling and maintenance; adding or replacing hardware takes time; scaling is limited by what you bought; you need a team watching the infrastructure 24/7; and a disaster (earthquake, power outage, fire) can take everything down. Cloud computing answers each of these.

Check yourself

Answer out loud before you open each card.

What does the browser need before it can send a request to caredesk.test?Show answer

The server's IP address, which it gets by asking a DNS server.

Router or switch: which one connects your office network to the internet?Show answer

The router. The switch connects machines inside the same network.

The web server is fine but the database is down. What does the user usually see?Show answer

An error page from the server (often HTTP 500). The request reached the server; the server couldn't finish the work.

Name three costs of running your own data centre besides the servers.Show answer

Any three of: rent, power, cooling, maintenance, and staff watching it 24/7.

Why do you end up either turning users away or paying for idle servers?Show answer

Because capacity is fixed by what you bought, while demand goes up and down. Buy for the average and peaks overflow; buy for the peak and most of the year it sits idle.

What single event can take a one-data-centre website offline completely?Show answer

A disaster at that site: power outage, fire, flood or earthquake. Everything is in one place.
