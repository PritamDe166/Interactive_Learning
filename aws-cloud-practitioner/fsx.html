Amazon FSx

  • Amazon FSx runs well-known third-party file systems as a managed service, for when EFS or S3 don't fit.
  • FSx for Windows File Server: a Windows share (SMB, NTFS) joined to Active Directory, reachable from AWS and on-premises.
  • FSx for Lustre (Linux + cluster): file storage for high performance computing, ML and analytics, often backed by S3.
  • Also FSx for NetApp ONTAP and FSx for OpenZFS for teams moving those systems to AWS.

Points to remember

  1. FSx = managed third-party, high-performance file systems. Four flavours; the exam focuses on Windows File Server and Lustre.
  2. FSx for Windows File Server: Windows-native shared file system, SMB protocol and NTFS, integrated with Microsoft Active Directory for user security.
  3. It can be deployed across two AZs (Multi-AZ) for high availability.
  4. Reachable from Windows EC2 instances and from on-premises machines (over VPN or Direct Connect).
  5. FSx for Lustre: "Lustre" = Linux + cluster. Fully managed, scalable storage for HPC: machine learning, analytics, video processing, financial modelling.
  6. Lustre performance: hundreds of GB/s, millions of IOPS, sub-millisecond latency.
  7. FSx for Lustre can link to an S3 bucket: S3 objects appear as files; results can be written back to S3.
  8. Exam triggers: "Windows file share / SMB / AD" → FSx for Windows. "HPC / high-performance computing" → FSx for Lustre. "Linux NFS share" → EFS.

Where to find it (no course lab; FSx is not free-tier)
  1. Amazon FSx → Create file system: choose Windows File Server, Lustre, NetApp ONTAP or OpenZFS.
  2. Windows: pick Multi-AZ or Single-AZ, storage size, and the Active Directory (AWS Managed Microsoft AD or your own).
  3. Lustre: pick a deployment type (scratch for short jobs, persistent for longer), and optionally a data repository association with an S3 bucket.
  4. Look only; delete anything you create. FSx bills per GB-month and throughput.

Cheat-sheet

  • Windows file share, SMB, NTFS, Active Directory→FSx for Windows File Server
  • High performance computing, ML training, S3-backed files→FSx for Lustre
  • Shared Linux NFS, general purpose→EFS
  • Moving NetApp storage to AWS as-is→FSx for NetApp ONTAP
