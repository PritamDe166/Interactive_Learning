AWS CLF-C02 / Amazon S3 / 4 · Domain 3 Technology

S3 Versioning

  • Versioning keeps every version of an object, so overwrites and deletes can be undone.
  • A normal delete adds a delete marker; removing the marker brings the object back.
  • Deleting a specific version ID is permanent.
  • Each version is billed as a full object. Versioning can be suspended but not turned off, and replication needs it.

In terms you know

AWSClosest thing you knowThe difference
VersioningSharePoint version history, or Volume Shadow Copies on a file shareKept per object for ever (until you expire or delete versions), and every version is billed.
Delete markerMoving a file to the Recycle BinNothing is removed; the object just stops appearing.

Points to remember

  1. Versioning is enabled per bucket. States: unversioned (default), Enabled, Suspended.
  2. An overwrite creates a new version; the previous one becomes noncurrent and is kept.
  3. DELETE without a version ID adds a delete marker: GET returns 404, but the data is still there. Remove the marker to restore.
  4. DELETE with a version ID permanently removes that version.
  5. Objects uploaded before versioning was enabled have version ID null.
  6. Every version is billed; lifecycle rules can expire noncurrent versions.
  7. MFA Delete requires a second factor for permanent deletes and versioning changes.
  8. Versioning is required for replication.

In the console

Turn on versioning and restore a deleted file (outline)
  1. Bucket → Properties → Bucket Versioning → Edit → Enable.
  2. Upload index.html, edit it locally, and upload it again.
  3. Turn on Show versions: you see both versions with their IDs.
  4. Delete the object (versions hidden): with Show versions on, a Delete marker appears. Delete the marker and the file is back.

Cheat-sheet

  • Recover an accidentally deleted or overwritten object→Versioning
  • Versioned delete without a version ID→Delete marker (GET = 404)
  • Undo a delete→Delete the delete marker
  • Permanent delete in a versioned bucket→Delete with a version ID
  • Turn versioning off→Only Suspend
  • Prerequisite for replication→Versioning
  • Extra protection for permanent deletes→MFA Delete

Object Lock (WORM: write once, read many) can stop versions being deleted or overwritten for a retention period, for compliance. It needs versioning.

Lifecycle for versions. A lifecycle rule can move noncurrent versions to a cheaper class and expire them after a number of days.

DELETE with its version ID.

null.

Does versioning change your bill?Show answer

Yes. Every stored version is billed as a full object.

Can you turn versioning off again?Show answer

No, only suspend it. Existing versions remain.
