Docker & Containers

  • A container packages an app with its runtime and libraries, so it runs the same everywhere.
  • A Dockerfile builds an image; images live in a registry (Docker Hub, Amazon ECR); hosts run them as containers.
  • Containers share the host OS, so they are lighter and faster than VMs.
  • Background for ECS, EKS, Fargate, ECR and Batch.

Points to remember

  1. Container = app + dependencies, running isolated on a shared host OS.
  2. Dockerfile → docker build → image → docker push → registry → docker run → container.
  3. Registries: Docker Hub (public), Amazon ECR (AWS, private or public).
  4. Containers start in seconds and pack densely; VMs each need a full guest OS.
  5. Docker runs on any OS; the same image runs on a laptop, on-premises or in AWS.
