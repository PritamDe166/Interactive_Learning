Databases & Analytics

  • Managed databases: AWS runs the hardware, OS, patching, backups and failover; you own the data, schema and access.
  • Relational (SQL, joins): RDS and Aurora. NoSQL (flexible schema, scales out): DynamoDB, DocumentDB, Neptune.
  • Multi-AZ = availability. Read replicas = read scaling. Don't swap them.
  • Analytics: Kinesis streams in, Glue prepares, Athena / Redshift / EMR query, QuickSight shows.

Exam cheat-sheet

  • Managed relational, automated backups→RDS
  • Automatic failover to another AZ→RDS Multi-AZ
  • Offload heavy reads / reports→Read replica
  • Serverless NoSQL, single-digit ms→DynamoDB
  • Reduce load from repeated queries→ElastiCache
  • Data warehouse, OLAP→Redshift

Aurora

AWS's own MySQL/PostgreSQL-compatible engine. Storage auto-grows (up to 256 TiB) with 6 copies across 3 AZs, up to 15 low-lag replicas. Aurora Serverless scales capacity per second for spiky or intermittent load.

DynamoDB

Serverless key-value/document NoSQL, single-digit ms at any scale, no joins. On-demand or provisioned capacity. DAX: microsecond cache, DynamoDB only. Global Tables: active-active across Regions.

Snapshots and backups

Automated backups with point-in-time restore. Restoring always creates a new database. Copy snapshots to another Region for DR, share them with other accounts. You can't SSH into RDS.

Kinesis

Real-time streaming. Data Streams: ingest and process events in real time. Data Firehose: deliver streams into S3, Redshift or OpenSearch with no code.

OpenSearch Service

Managed search and log analytics (Elasticsearch fork): full-text search, log dashboards. Trigger: "search", "log analytics".

Migrating databases

DMS moves data while the source stays online (and keeps replicating). SCT converts the schema when engines differ (Oracle → Aurora PostgreSQL).

Updated

Multi-AZ now has two forms. A Multi-AZ DB instance has one standby that can't serve reads (the classic exam answer). A Multi-AZ DB cluster has two standbys in three AZs that can serve reads. For the exam: Multi-AZ = HA.

Updated

Aurora's marketing number changed: AWS now quotes up to 6× the throughput of MySQL and PostgreSQL (the course says 5× / 3×). If only one is offered, go with the course wording. Aurora Serverless v2 scales in 0.5 ACU steps and can scale to zero.

Updated

Timestream for LiveAnalytics has an end-of-support notice; AWS points to Timestream for InfluxDB. ElastiCache now offers Valkey as well as Redis OSS and Memcached. Managed Blockchain supports Ethereum, Hyperledger Fabric and more.

Added

In scope but missing from the notes: Kinesis, OpenSearch Service and SCT (cards above). Out of scope: Keyspaces, MemoryDB, MSK. Timestream and Managed Blockchain are on neither list: know only the trigger word.

Check yourself

Answer out loud before you open each card.

Which RDS feature gives automatic failover to another AZ?Show answer

Multi-AZ. Read replicas need manual promotion and may lose recent writes.

Reports are slowing down the production database. What do you add?Show answer

A read replica and point the reports at it (or a cache like ElastiCache for repeated reads).

SQL on CSV/Parquet files in S3 without loading data or servers?Show answer

Athena, billed per TB scanned; Parquet and compression cut the bill.

MongoDB workload, managed on AWS?Show answer

DocumentDB.

OLAP, columnar, petabyte data warehouse?Show answer

Redshift. (RDS/Aurora are OLTP.)

Migrate Oracle on-prem to Aurora with minimal downtime: which two services?Show answer

SCT converts the schema, DMS moves the data and keeps it in sync until cut-over.
