EC2 Image Builder

  • EC2 Image Builder automates making AMIs: build → test → distribute, on a schedule or when packages update.
  • It launches a temporary builder instance, installs your components, and creates the AMI.
  • It can launch a test instance from the new AMI and run your tests, then copy the AMI to several Regions.
  • The service is free; you pay for the EC2 instances it runs and the AMI storage.

Points to remember

  1. EC2 Image Builder automates the creation, maintenance, validation and testing of AMIs (and container images).
  2. Build: a builder EC2 instance is launched and your components run on it (install Java, update the CLI, patch the OS, install a firewall…). Then an AMI is created from it.
  3. Test (optional): a test EC2 instance is launched from the new AMI and your tests run (does it boot, is the app up, is it secure).
  4. Distribute: the AMI is copied to multiple Regions, so apps everywhere use the same image.
  5. Runs on a schedule (e.g. weekly), when package updates are available, or manually.
  6. Pricing: the service is free; you pay for the builder/test instances while they run and AMI storage in each Region.
  7. Exam trigger: "automate the creation / patching of AMIs" → EC2 Image Builder.

    Which tool?

    In the console

    Create a pipeline (outline; the course shows it, no lab required)
    1. EC2 Image Builder → Create image pipeline, name it, set the build schedule (manual, cron, or when dependency updates are available).
    2. Recipe: output type AMI, base image (e.g. Amazon Linux 2023), add build components (e.g. aws-cli-version-2-linux, amazon-corretto-11) and optional test components.
    3. Infrastructure configuration: instance type for the builder and an IAM role with EC2InstanceProfileForImageBuilder and AmazonSSMManagedInstanceCore.
    4. Distribution settings: the Regions (and accounts) to copy the AMI to.
    5. Run it. Watch the builder and test instances appear in EC2, then the AMI appear under AMIs. Clean up the AMI and pipeline afterwards.
