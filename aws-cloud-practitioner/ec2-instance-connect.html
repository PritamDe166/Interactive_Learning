EC2 Instance Connect

  • EC2 Instance Connect opens an SSH terminal in your browser from the EC2 console: no local terminal, no PuTTY, no .pem to manage.
  • Behind the scenes AWS pushes a one-time public key to the instance (valid for about 60 seconds) and connects over SSH, port 22.
  • So the security group must still allow SSH 22, from the Instance Connect service's addresses (in the lab: anywhere).
  • Works on supported AMIs like Amazon Linux and Ubuntu; user ec2-user.

Points to remember

  1. Browser-based SSH from the console: Instance → Connect → EC2 Instance Connect → Connect, user ec2-user.
  2. AWS generates and pushes a temporary SSH key for the session (about 60 seconds to use it). You don't download or store a key.
  3. It is still SSH on port 22: the security group must allow it. A rule for "My IP" only won't work, because the browser session connects from AWS's Instance Connect address range.
  4. The instance needs a public IP (for this basic mode) and a supported AMI with Instance Connect installed (Amazon Linux 2/2023, Ubuntu).
  5. Your IAM identity needs permission to use it (ec2-instance-connect:SendSSHPublicKey); AdministratorAccess covers it.
  6. Test with whoami → ec2-user. Commands run on the instance, like normal SSH.
  7. Later: Systems Manager Session Manager gives shell access with no port 22 at all (Deployment section).

In the console

Connect from the browser (from the course hands-on)
  1. EC2 → Instances → select the running instance → Connect.
  2. Tab EC2 Instance Connect; check the public IPv4; user name ec2-user; Connect.
  3. A terminal opens in a new tab. Run whoami, ping google.com (Ctrl+C to stop).
  4. If it fails: open the security group → Edit inbound rules → add SSH 22 (IPv4, and IPv6 if your setup uses it) → retry.

Cheat-sheet

  • SSH from the browser, no key file→EC2 Instance Connect
  • Instance Connect fails with a timeout→Allow SSH 22 in the security group
  • Shell access with no inbound port open→SSM Session Manager
