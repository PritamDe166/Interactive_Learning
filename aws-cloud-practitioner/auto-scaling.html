AWS CLF-C02 / ELB & Auto Scaling / 3 · Domain 3 Technology

EC2 Auto Scaling Groups

  • An Auto Scaling group (ASG) keeps the right number of EC2 instances running: it adds them when load rises and removes them when it falls.
  • You set a minimum, a desired and a maximum count; a launch template says what each new instance looks like.
  • It replaces unhealthy instances and spreads them across Availability Zones.
  • New instances are registered with the load balancer automatically. The ASG itself is free; you pay for the instances.

Points to remember

  1. An ASG scales out (adds instances) when load rises and scales in (removes them) when it falls.
  2. It keeps the count between a minimum and a maximum; desired capacity is how many should run right now.
  3. A launch template holds the AMI, instance type, key pair, security groups and user data for new instances. Launch configurations are the older, deprecated form.
  4. New instances are registered with the load balancer's target group; removed ones are deregistered first, so current requests can finish.
  5. It replaces unhealthy instances. By default it uses EC2 status checks; turn on ELB health checks so an instance whose app has failed is replaced too.
  6. Spread the ASG across several AZs: if an AZ fails, it launches replacements in the others.
  7. The ASG is free; you pay for the EC2 instances it launches. It can mix On-Demand and Spot instances.

    In the console

    Create an Auto Scaling group behind a load balancer (outline)
    1. EC2 → Launch templates → Create: Amazon Linux 2023 AMI, t3.micro, a security group, and user data that installs a small web server.
    2. EC2 → Auto Scaling groups → Create: choose the launch template, the VPC and subnets in at least two AZs.
    3. Attach to an existing load balancer: pick the target group from the ALB topic. Turn on Elastic Load Balancing health checks.
    4. Group size: desired 2, minimum 1, maximum 4. Optionally add a target tracking policy (for example average CPU 50%).
    5. Watch the Activity tab launch two instances; they appear as healthy targets behind the load balancer.
    6. Terminate one instance yourself: the ASG notices and launches a replacement. Set desired to 0 or delete the group to clean up.

    Cheat-sheet

    • Add instances when load rises, remove them when it falls→Auto Scaling group
    • Always keep at least N instances running→ASG minimum capacity
    • Replace a crashed instance automatically→ASG (with ELB health checks)
    • Spread instances across data centres→Multi-AZ ASG
    • What each new instance looks like→Launch template
    • Spread requests across the instances→Load balancer, not the ASG
    • How much does the ASG cost?→Nothing; you pay for the instances

    Launch configurations are deprecated. Accounts created on or after 1 October 2024 can't create new ones. Use launch templates, which also support versions, Spot and mixed instance types.

    Scaling in picks carefully. By default the ASG first balances AZs (it removes from the AZ with the most instances), then prefers instances from the oldest launch template. You can protect particular instances from scale-in.

    Instance refresh replaces running instances in batches after you change the launch template, for example to roll out a new AMI.

    Amazon EC2 Auto Scaling vs AWS Auto Scaling. EC2 Auto Scaling manages ASGs of instances. AWS Auto Scaling is a separate console for scaling plans across several services (EC2, ECS, DynamoDB, Aurora). For the exam, "scale EC2 instances" means an ASG.

    Check yourself

    Answer out loud before you open each card.

    Min 2, desired 3, max 6. One instance is terminated. What happens?Show answer

    Only 2 are running but desired is 3, so the ASG launches a replacement.

    The web app on an instance hangs, but the instance itself is fine. Will the ASG replace it?Show answer

    Only if ELB health checks are turned on for the ASG. EC2 status checks only see the instance and its hardware, not your app.

    Where does the ASG get the AMI and instance type for new instances?Show answer

    From the launch template.

    An AZ fails. What does a multi-AZ ASG do?Show answer

    It launches replacement instances in the remaining AZs to get back to desired capacity, and rebalances when the AZ returns.

    How much does an Auto Scaling group cost?Show answer

    Nothing. You pay only for the instances (and other resources) it launches.

    Does the ASG spread requests across the instances?Show answer

    No. The load balancer spreads requests. The ASG decides how many instances exist and registers them with the load balancer.
