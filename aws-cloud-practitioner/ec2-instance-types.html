EC2 instance types

  • Instance types are tuned for different bottlenecks: balanced, CPU, memory, local storage, or GPUs.
  • General purpose (T, M) · Compute optimized (C) · Memory optimized (R, X) · Storage optimized (I, D, H) · Accelerated (P, G).
  • A name like m5.2xlarge reads: family m, generation 5, size 2xlarge.
  • Bigger size = more vCPUs, memory, network and cost. Pick the family for the bottleneck, then the size.

Points to remember

  1. Name: m5.2xlarge = family m · generation 5 · size 2xlarge. Extra letters after the generation are attributes (g Graviton/Arm, i Intel, a AMD, d local NVMe…).
  2. General purpose (T, M): balanced; web servers, code repositories, dev/test. t2.micro/t3.micro are the Free Tier examples. T = burstable.
  3. Compute optimized (C): high CPU; batch processing, media transcoding, high-performance web servers, HPC, scientific modelling and ML, dedicated game servers.
  4. Memory optimized (R, X, z): large data sets in RAM; high-performance relational/NoSQL databases, in-memory caches, web-scale caches, real-time big data, BI.
  5. Storage optimized (I, D, H): very fast local storage; high-frequency OLTP, relational and NoSQL databases, Redis-style caches, data warehouses, distributed file systems.
  6. Accelerated computing (P, G, Inf, Trn): GPUs or AWS ML chips for training, inference and graphics.
  7. Same vCPU count ≠ same use: c5.4xlarge has 16 vCPU and 32 GiB; r5.4xlarge 16 vCPU and 128 GiB.
  8. Compare vCPU, memory, network, EBS bandwidth, local storage and price per Region (AWS instance types page; ec2instances.info is a handy comparison site).

Exam cheat-sheet

  • Balanced web server, dev box→General purpose (T, M)
  • Batch, transcoding, HPC, gaming servers→Compute optimized (C)
  • In-memory database, big cache, real-time analytics→Memory optimized (R)
  • High-IOPS OLTP on local disk, data warehouse→Storage optimized (I, D, H)
  • ML training, GPUs→Accelerated computing (P, G)
