AWS CLF-C02 / Other compute / Section review

Other compute: review

  • Containers: images in ECR, run by ECS (AWS) or EKS (Kubernetes), on EC2 or serverless Fargate.
  • Serverless: no servers to manage; Lambda, Fargate, S3, DynamoDB, API Gateway.
  • Lambda: event-driven functions, 15 min, 10 GB, pay per request + GB-second. API Gateway exposes them as APIs.
  • Batch: long Docker jobs on Spot. Lightsail: simple, predictable-price bundles.

Section summary

Containers

  • Docker image → registry → container; shared host OS.
  • ECR stores images; ECS runs containers (EC2 launch type = your instances).
  • Fargate = serverless containers (ECS and EKS).
  • EKS = managed Kubernetes; pods on EC2 or Fargate.

Serverless & Lambda

  • Serverless = no servers to see; scales; pay per use.
  • Lambda: events (S3, EventBridge, API Gateway…), 15 min max, 128 MB–10 GB.
  • Pricing: $0.20 per 1M requests + GB-seconds; free tier 1M + 400,000 GB-s.
  • Execution role for permissions; CloudWatch Logs.

APIs, batch, simple

  • API Gateway: REST/HTTP/WebSocket, auth, API keys, throttling.
  • Batch: Docker jobs in a queue, EC2/Spot or Fargate, no time limit, managed not serverless.
  • Lightsail: beginner bundles, predictable price, no auto scaling.

PairThe difference

ECS vs ECRRuns containers vs stores images
Lambda vs Batch15-minute functions vs Docker jobs of any length
Lambda vs EC2Runs per event, billed per use vs always-on server
Serverless vs managedNo servers to see (Lambda, Fargate) vs AWS-run on your instances (ECS on EC2, Batch)
API Gateway vs ALBServerless API features (keys, throttling) vs load balancing for EC2/containers
Lightsail vs EC2Simple fixed bundles vs full control and auto scaling
