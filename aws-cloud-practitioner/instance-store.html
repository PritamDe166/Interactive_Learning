EC2 instance store

  • An instance store is a disk physically inside the host server your instance runs on, not a network drive.
  • No network in the way, so it is extremely fast (millions of IOPS on storage-optimized types like I3).
  • It is ephemeral: data is lost on stop, terminate or host failure (it survives a reboot).
  • Use it for cache, buffers, scratch data; backups and replication are your job.

Points to remember

  1. Instance store = hardware disk attached to the physical host. EBS = network drive.
  2. Only some instance types have it (e.g. the storage-optimized I family, types with a "d" like m5d); size is fixed by the type and it's included in the price.
  3. Very high IOPS and throughput, much more than EBS, because there's no network hop.
  4. Ephemeral: lost on stop, hibernate, terminate and underlying hardware failure. Survives a reboot.
  5. Good for buffers, caches, scratch/temporary data, or data already replicated across several instances.
  6. Backups and replication are your responsibility (shared responsibility model).
  7. Exam trigger: "very high-performance, hardware-attached / local storage" → instance store. "Persistent" → EBS.

EBS or instance store?

In the console

Where you'd see it (no course lab)
  1. In the launch wizard, pick a type with local storage (e.g. i3.large or m5d.large); the type details show "Instance storage: 1 x 475 GB NVMe SSD".
  2. Storage section of the wizard: the instance store volume appears next to the EBS root, without a Delete-on-termination option (it always disappears).
  3. Don't run it for long: I3 types are expensive. Terminate after looking.

Cheat-sheet

  • Highest disk I/O for one instance→Instance store
  • Cache, buffer, scratch, temp files→Instance store
  • Data must survive stop/terminate→EBS (or EFS)
  • Who backs up instance store data?→The customer

Check yourself

Why is instance store faster than EBS?Show answer

It is a disk in the host server; there is no network between the instance and the disk.

You stop and start an i3 instance. What happens to the instance store data?Show answer

Lost. The instance may start on a different host with a fresh, empty instance store.

Is instance store a good place for a database's only copy?Show answer

No. Use EBS, or replicate the data to other instances if you need instance-store speed.
