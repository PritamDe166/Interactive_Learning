Amazon Route 53

  • Route 53 is managed DNS (and a domain registrar), with a 100% availability SLA.
  • Records map names to IPs or, with Alias, to AWS resources such as load balancers.
  • Routing policies decide which answer each user gets: simple, weighted, latency, failover, geolocation…
  • Health checks let it avoid failed endpoints.

In terms you know

AWSClosest thing you knowThe difference
Route 53Your company's DNS servers (Windows DNS) on the internetGlobal, managed, and able to answer differently per user.
Failover routingChanging the DNS record to the DR site when the primary is downAutomatic, driven by health checks.

Points to remember

  1. Route 53 = managed DNS; also domain registration and health checks.
  2. Records: A (IPv4), AAAA (IPv6), CNAME, Alias (AWS resources, free queries).
  3. Policies: Simple, Weighted, Latency, Failover (DR), Geolocation, Geoproximity, Multivalue, IP-based.
  4. Route 53 decides where users go; it doesn't speed up the transfer itself.

In the console

Latency routing between two Regions (outline)
  1. Run a small web server (or ALB) in two Regions.
  2. Route 53 → Hosted zones → your domain → Create record: same name, routing policy Latency, one record per Region with its IP or Alias.
  3. Add a health check for each endpoint.
  4. Query the name from different places (or a VPN): each answer is the nearer Region.

Cheat-sheet

  • Managed DNS / register a domain→Route 53
  • Lowest latency Region per user→Latency routing
  • Disaster recovery via DNS→Failover routing
  • Send 10% of traffic to a new version→Weighted routing
  • Route by user's country→Geolocation routing

Reference

PolicyAnswer chosen by
SimpleOne record, no health checks
WeightedPercentages you set
LatencyLowest latency for the user
