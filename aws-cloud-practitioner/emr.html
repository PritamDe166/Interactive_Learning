AWS CLF-C02 / Databases & analytics / 8 · Domain 3 Technology

Amazon EMR

  • EMR (Elastic MapReduce) runs big-data frameworks: Spark, Hadoop, Hive, Presto, HBase, Flink.
  • It creates a cluster of EC2 instances and configures it for you; data usually lives in S3.
  • More nodes finish sooner; Spot task nodes cut cost; clusters can auto scale and shut down after the job.
  • It processes data; it is not a database.

In terms you know

AWSClosest thing you knowThe difference
EMRA Hadoop or Spark cluster your data team would build on dozens of serversReady in minutes, billed per second, gone when the job ends.

Walkthrough: crunching 50 TB of clinic logs

Points to remember

  1. EMR = managed Hadoop / Spark big-data platform on EC2 clusters.
  2. Node roles: primary (coordinates), core (tasks + HDFS storage), task (tasks only).
  3. Integrates with S3 for input and output; clusters can be transient.
  4. Spot Instances and auto scaling reduce cost; EMR Serverless removes cluster management.
  5. Uses: log processing, ETL at scale, machine learning, big-data analytics.

EMR or something else?

Pick the service

Cheat-sheet

  • Hadoop, Spark, big-data cluster→EMR
  • Cheap, interruptible workers for EMR→Spot Instances (task nodes)
  • Spark without managing a cluster→EMR Serverless
  • Serverless SQL on S3→Athena, not EMR

Reference

NodeRole
PrimaryCoordinates the cluster and tracks tasks
CoreRuns tasks and stores data in HDFS
TaskRuns tasks only; good on Spot
