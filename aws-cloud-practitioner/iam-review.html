IAM: review

  • IAM decides who gets in and what they can do, for every console click, CLI command and SDK call.
  • Identities: root user (one, locked away), IAM users (people), groups (sets of users), roles (assumed, temporary).
  • Permissions come from JSON policies: default deny, explicit Deny wins, Allow grants.
  • Keep it safe: MFA, password policy, least privilege, roles instead of keys, regular audits. That configuration is your responsibility.

Section summary

Users & groups

  • IAM is global; authentication + authorization.
  • One user per person; groups contain users only, no nesting; a user can be in many groups.
  • Policies on groups are inherited; default deny; least privilege.

Root vs IAM user

  • Exactly one root user, full access, MFA, no access keys.
  • Root-only: close account, change account email/root password, restore locked-out admin, IAM billing access, S3 MFA Delete, RI Marketplace seller.
  • IAM users belong to one account.

Policies

  • Version 2012-10-17; Statement: Effect, Action, Resource, optional Sid, Condition.
  • Principal in resource-based policies.
  • Default deny → explicit Deny wins → Allow. Permissions add up.
  • AWS managed / customer managed / inline. SCPs and boundaries only limit.

Access methods

  • Console (password + MFA), CLI, SDK: same APIs, same IAM check.
  • Access key = key ID + secret; never commit; max two per user; rotate.
  • Prefer temporary credentials; aws sts get-caller-identity.
  • CloudShell: browser CLI as your identity, per-Region storage (out of exam scope).

Roles

  • No long-term credentials; assumed for temporary credentials from STS.
  • Trust policy (who) + permissions policy (what).
  • EC2 instance role, Lambda execution role, CloudFormation, cross-account, federation.

Tools & best practices

  • Credential report: account-wide CSV of credential status.
  • Access Advisor: services used and when, per user/group/role/policy.
  • MFA, password policy, roles, key hygiene, Secrets Manager.
  • AWS runs IAM; you configure it.

Section cheat-sheet

  • Who can do what in AWS→IAM
  • Account owner, full access, use rarely→Root user
  • Collection of IAM users→IAM group
  • JSON document of permissions→IAM policy
  • EC2 / Lambda needs AWS permissions→IAM role
  • Access another account's resources→Cross-account role
  • Single sign-on for the workforce across accounts→IAM Identity Center
  • Extra factor after the password→MFA
  • Enforce strong passwords→Password policy
  • Run commands in a terminal / call AWS from code→AWS CLI / AWS SDK
  • Users without MFA, old keys→Credential report
  • Services a user last used→Access Advisor
  • Store database passwords→Secrets Manager
  • Explicit Deny vs Allow→Deny wins
  • Who configures IAM and enables MFA→The customer
