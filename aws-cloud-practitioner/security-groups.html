Security groups & classic ports

  • A security group is a virtual firewall around EC2 instances, with inbound and outbound rules.
  • It has allow rules only. Inbound is blocked by default; outbound is allowed by default. Replies to allowed traffic flow back automatically (stateful).
  • A rule = protocol + port + source: an IP range (0.0.0.0/0, 203.0.113.10/32) or another security group.
  • Timeout = blocked by the security group. Connection refused = it got through, but nothing is listening.

Points to remember

  1. Security group = virtual firewall for EC2 (and other resources like RDS), outside the instance. Blocked traffic never reaches the OS.
  2. Rules are allow-only: there is no "deny" rule. Anything not allowed is dropped.
  3. Default: all inbound blocked, all outbound allowed.
  4. Stateful: if a request is allowed in, its reply goes out automatically (and vice versa).
  5. Rule = type/protocol, port (or range), source: CIDR (0.0.0.0/0 = all IPv4, x.x.x.x/32 = one IP), IPv6 range, or another security group.
  6. Referencing a security group keeps working when instances' IPs change, which suits app tiers and load balancers.
  7. Many-to-many: one group on many instances; one instance with several groups (rules combine). Groups are tied to a Region and VPC.
  8. Keep SSH in its own group, open only to your IP. Opening 443 isn't enough for HTTPS; the server also needs a certificate.
  9. Ports: 21 FTP · 22 SSH and SFTP · 80 HTTP · 443 HTTPS · 3389 RDP (Windows).

In the console

Break and fix a rule (from the course hands-on)
  1. EC2 → your instance → Security tab: see the attached group (e.g. launch-wizard-1) and its rules. Or Network & Security → Security Groups.
  2. Inbound rules: SSH 22 and HTTP 80 from Anywhere IPv4 (0.0.0.0/0).
  3. Edit inbound rules → delete HTTP 80 → save. Refresh the website: it hangs, then times out.
  4. Add HTTP 80 back → save → refresh: the page loads again.
  5. Explore sources: Anywhere, My IP (breaks if your IP changes), a custom CIDR, another security group, a prefix list.
  6. Outbound rules: one default rule allowing all traffic.

Exam cheat-sheet

  • Instance-level firewall, stateful, allow only→Security group
  • Connection times out→Security group (inbound rule missing)
  • Connection refused→Application not running / not listening
  • Linux admin / Windows admin→SSH 22 / RDP 3389
  • Who configures security group rules?→The customer

Added

Stateful vs stateless: security groups are stateful (replies allowed automatically). Network ACLs, at the subnet level, are stateless and can have deny rules; they come in the VPC section.
