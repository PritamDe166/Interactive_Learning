Amazon ECS, Fargate & ECR

  • ECR stores your container images.
  • ECS runs containers on AWS: with the EC2 launch type you provide and patch the instances.
  • Fargate runs the same containers serverless: you only set CPU and memory.
  • ECS integrates with the Application Load Balancer.

In terms you know

Points to remember

  1. ECR = Elastic Container Registry: stores Docker/container images.
  2. ECS = Elastic Container Service: AWS's container orchestrator; tasks and services; ALB integration.
  3. ECS EC2 launch type: you provision and maintain the EC2 instances.
  4. Fargate: serverless compute for containers; set CPU and RAM per task; works with ECS and EKS.
  5. Pricing: ECS on EC2 = instances; Fargate = vCPU and memory per second.
  6. Shared responsibility: with Fargate AWS manages the servers and OS; with EC2 launch type you do.

In the console

Run a container on Fargate (outline)
  1. ECR → Create repository, then push an image with the commands the console shows (or use a public image such as nginx).
  2. ECS → Create cluster (Fargate only).
  3. Task definitions → Create: launch type Fargate, 0.5 vCPU, 1 GB, container image and port 80.
  4. Cluster → Services → Create: 2 tasks, optionally behind a new Application Load Balancer.
  5. Open the load balancer DNS name; then set desired tasks to 0 and delete the service and cluster.

Cheat-sheet

  • Run Docker containers on AWS→ECS
  • Containers without managing servers→Fargate
  • Store container images→ECR
  • Least operational overhead for containers→Fargate
  • Who patches ECS EC2 hosts?→You
