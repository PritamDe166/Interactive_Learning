EFS and EFS-IA

  • Amazon EFS (Elastic File System) is a managed NFS network file system: one shared folder for many instances.
  • Hundreds of Linux instances in different AZs mount it at once and see the same files.
  • No capacity planning: it grows and shrinks, and you pay per GB actually stored (pricier per GB than EBS).
  • A lifecycle policy moves cold files to EFS-IA (up to 95% cheaper) and Archive, invisibly to apps.

Points to remember

  1. EFS = managed NFS (network file system) that can be mounted on hundreds of EC2 instances at the same time.
  2. Works across multiple AZs in a Region (Regional file system), through one mount target per AZ protected by a security group (NFS port 2049).
  3. Linux instances only (POSIX/NFS). Windows file shares → FSx for Windows File Server.
  4. Highly available, scalable, pay per use: no capacity to provision; 20 GB stored = 20 GB billed.
  5. Costs roughly 3× an EBS gp2 volume per GB, the price of being shared and multi-AZ.
  6. EFS vs EBS: EBS = one instance, one AZ; moving it across AZs makes a copy via snapshot. EFS = shared, live, already in every AZ.
  7. Storage classes: Standard (frequent), Infrequent Access (EFS-IA) up to 95% cheaper, Archive up to 50% cheaper than IA (rarely read).
  8. A lifecycle policy (e.g. "not accessed for 60 days → IA") moves files automatically and moves them back on access. Transparent to applications; IA/Archive charge per GB read.
  9. One Zone classes also exist: cheaper, data in a single AZ (dev/test, or data you can recreate).

EFS or EBS?

In the console

Create and mount a file system (outline)
  1. EFS → Create file system, name it, choose the VPC. "Regional" keeps data across AZs (One Zone is the cheaper single-AZ option).
  2. Customize: lifecycle management (e.g. to IA after 30 days, to Archive after 90), throughput mode Elastic.
  3. Network: one mount target per AZ, each with a security group that allows NFS (2049) from the instances' security group.
  4. Launch Linux instances in two AZs; in the launch wizard's File systems section, add the EFS (it mounts at e.g. /mnt/efs/fs1).
  5. Create a file on one instance, ls on the other: it's there. Clean up instances and the file system.

Cheat-sheet

  • Shared file system for many Linux instances→EFS
  • Shared across AZs, no capacity planning→EFS
  • Cut cost of rarely used files in EFS→EFS-IA via lifecycle policy
  • Shared file system for Windows→FSx for Windows File Server
  • Disk for a single instance→EBS

Check yourself

Can a Windows EC2 instance mount EFS?Show answer

No. EFS is NFS for Linux. Use FSx for Windows File Server.

Do you choose a size when creating EFS?Show answer

No. It grows and shrinks; you pay for what is stored.

Does an app need changes when its files move to EFS-IA?Show answer

No. Same path; the lifecycle policy is transparent (reads from IA just cost a little per GB).

Web servers in 3 AZs must share uploaded images. EBS or EFS?Show answer

EFS: shared and multi-AZ. EBS is one instance in one AZ.

What does each AZ need to reach EFS?Show answer

A mount target, with a security group allowing NFS (2049).

Why is EFS more expensive per GB than EBS?Show answer

It is shared, highly available across AZs, and elastic; you pay for that convenience (IA and Archive offset it).
