AWS CLF-C02 / Amazon S3 / 9 · Domain 3 Technology

AWS Storage Gateway

  • Storage Gateway connects on-premises servers to AWS storage: hybrid cloud storage.
  • It runs in your data centre and speaks the protocols your servers already use.
  • Three types: S3 File Gateway (SMB/NFS), Volume Gateway (iSCSI), Tape Gateway (virtual tapes).
  • Data lands in S3, S3 Glacier or as EBS snapshots, with a local cache for speed.

Points to remember

  1. Storage Gateway = a bridge between on-premises data and AWS storage (hybrid cloud).
  2. S3 File Gateway: SMB or NFS file shares; files stored as S3 objects.
  3. Volume Gateway: iSCSI block volumes backed by S3, with EBS snapshots.
  4. Tape Gateway: a virtual tape library (VTL) for backup software; tapes stored in S3 and S3 Glacier.
  5. Runs as a VM on-premises (VMware, Hyper-V, KVM) or as a hardware appliance; keeps a local cache.
  6. Use cases: backup and restore, disaster recovery, tiered storage, moving file shares to the cloud.

Match the on-premises need

Cheat-sheet

  • On-premises app needs S3 through NFS/SMB→S3 File Gateway
  • Replace physical tapes→Tape Gateway
  • iSCSI volumes backed up to AWS→Volume Gateway
  • Hybrid cloud storage→Storage Gateway
  • One-off bulk move of data→Not Storage Gateway: DataSync or a Snowball device

Reference

TypeYour servers seeStored in AWS as
S3 File GatewaySMB / NFS file shareS3 objects

Tape GatewayVirtual tape library (iSCSI VTL)Virtual tapes in S3 and S3 Glacier

Ongoing access vs moving data once. Storage Gateway is for continuous hybrid use. To move a large amount of data once, use AWS DataSync over the network or a physical AWS Snowball device. AWS has announced that Snowball devices will no longer be supported in commercial Regions after 31 December 2026.

FSx File Gateway gives on-premises low-latency access to Amazon FSx for Windows File Server shares.
