AWS CLF-C02 / ELB & Auto Scaling / 1 · Domain 1 Cloud Concepts & Domain 3 Technology

High Availability, Scalability and Elasticity

  • Scalability means the app can handle more load. Vertical scaling uses a bigger instance (scale up). Horizontal scaling adds more instances (scale out).
  • Elasticity means scaling happens automatically as demand changes, so you pay only for what runs.
  • High availability means running in at least two Availability Zones, so losing one data centre doesn't stop the app.
  • Agility is a different benefit: new resources in minutes instead of weeks. The exam uses it as a distractor.

Points to remember

  1. Scalability: the system can handle a larger load by adapting.
  2. Vertical scaling (scale up or down) changes the size of one instance, for example t3.micro → t3.large. It suits systems that don't split well, like a single database. There is a hardware limit, and resizing an EC2 instance means stopping it.
  3. Horizontal scaling (scale out or in) changes the number of instances. The app must be distributed: each instance works on its own, so the app keeps no state on one server (stateless). On AWS this is done by an Auto Scaling group.
  4. Elasticity is horizontal scaling that happens automatically with demand. You don't size for the peak all year, so you pay only for what you use.
  5. High availability (HA): run the app in at least 2 Availability Zones to survive the loss of a data centre (power cut, fire, flood).
  6. On AWS, HA and elasticity come from a multi-AZ Auto Scaling group plus a multi-AZ load balancer, the next two topics.
  7. Agility: new IT resources are "a click away", so getting them takes minutes instead of weeks. It is not the same as scalability or elasticity.

Cheat-sheet

  • Survive the failure of one AZ→High availability: run in at least 2 AZs
  • Change to a bigger instance type→Vertical scaling (scale up)
  • Add more instances→Horizontal scaling (scale out)
  • Add and remove capacity automatically with demand→Elasticity (Auto Scaling)
  • Resources in minutes instead of weeks→Agility
  • Don't pay for peak capacity all year→Elasticity

Horizontal does not mean elastic. If a person has to add the instances by hand, the system scales horizontally but is not elastic. Elasticity is the automatic part.

High availability vs disaster recovery. Two or more AZs survive a data-centre failure inside one Region. Running in a second Region is about disaster recovery and lower latency for distant users; that is covered in Global Infrastructure.

How big can vertical go? EC2 sizes range from instances with under 1 GB of memory to high-memory instances with many terabytes. The largest types change as AWS releases new ones, so the exam asks about the idea, not the numbers.

Fault tolerance is a close cousin of high availability: the system keeps working while a part fails, often with no visible effect. In questions, "survive the loss of an AZ" points to multi-AZ.

Check yourself

Answer out loud before you open each card.

You move the app from t3.micro to t3.xlarge. Which kind of scaling is that?Show answer

Vertical scaling (scale up): the same instance gets bigger.

An administrator adds two instances every Monday by hand. Is that elastic?Show answer

No. It is horizontal scaling, but elasticity means it happens automatically with demand.

What is the minimum number of AZs for high availability?Show answer

Two. With one AZ, a single data-centre failure stops the app.

"We can create a test environment in ten minutes." Which benefit is that?Show answer

Agility: fast access to resources. It is not elasticity.

Why does horizontal scaling need a distributed (stateless) app?Show answer

Each request may land on any instance. If one server kept a user's session in memory, the next request on another server would not find it.

Which two AWS services together give high availability and elasticity?Show answer

An Elastic Load Balancer and an Auto Scaling group, both spread across several AZs.
