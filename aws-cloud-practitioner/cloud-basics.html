Cloud Computing Basics

  • Cloud computing = on-demand IT (compute, storage, databases, networking) over the internet.
  • Pay as you go: rent instead of buy, scale in minutes instead of months.
  • You choose how much of the stack you manage: IaaS, PaaS or SaaS.
  • AWS runs in Regions, each made of isolated Availability Zones, plus edge locations near users.

Six advantages AWS lists (exam favourite)

CAPEX → OPEX

Trade upfront hardware purchases for a variable bill. You pay only for what you use.

Economies of scale

AWS buys at huge scale, so the usage price is lower than you'd pay on your own.

Stop guessing capacity

Scale up or down with demand instead of forecasting years ahead (the chart above).

Speed and agility

New resources in minutes, not weeks, so it's cheap to experiment.

No data centres to run

Spend effort on customers and apps, not racking servers and cooling.

Go global in minutes

Deploy in Regions around the world for lower latency.

How to choose a Region

1 · Compliance

Data residency laws come first. Indian patient records that must stay in India → ap-south-1 (Mumbai) or ap-south-2 (Hyderabad).

2 · Latency

Be close to your users. US customers get a US Region (or CloudFront in front).

3 · Service availability

New services and features don't launch everywhere at once. Check the Region list.

4 · Pricing

Prices differ by Region, and so does data transfer between them.

Added

An edge location is not an Availability Zone. You don't run EC2 there; CloudFront caches and serves content there. Your origin stays in a Region.

Added

Other places AWS can run your workload (Task 3.2 of the exam guide): Local Zones (a Region extension in a big city for single-digit-millisecond latency), Wavelength Zones (inside 5G telecom networks) and Outposts (AWS hardware in your own data centre).

Added

Deployment models: public cloud (AWS, Azure, GCP), private cloud (one organisation, more control) and hybrid (keep some servers on-premises, extend into the cloud). The five characteristics: on-demand self-service, broad network access, resource pooling (multi-tenancy), rapid elasticity, and measured service (pay per use).

Added

Pricing fundamentals: you pay for compute (time or capacity used), storage (data stored, plus requests), and data transfer out. Data transfer into AWS is generally free; data going out to the internet or across Regions is charged.

Check yourself

Answer out loud before you open each card.

A team uploads code and never touches the OS or runtime. IaaS, PaaS or SaaS? Name the AWS service.Show answer

PaaS: AWS Elastic Beanstalk. EC2 would be IaaS (you patch the OS); Gmail-style finished apps are SaaS.

"Pay only for what you use instead of buying hardware upfront." Which advantage?Show answer

Trade capital expense for variable (operational) expense, CAPEX → OPEX.

How do you survive the loss of one data centre in AWS?Show answer

Deploy across multiple Availability Zones (with a load balancer). AZs are isolated so one failure doesn't take the others down.

Patient data must legally stay in India. Which Region factor decides first?Show answer

Compliance / data residency. Latency, services and price only matter among Regions that are legally allowed.

Is an edge location where you run EC2 instances close to users?Show answer

No. Edge locations serve CloudFront (and some other edge services). For compute near users, look at Local Zones or Wavelength.

Name two global services and two Regional ones.Show answer

Global: IAM, Route 53, CloudFront. Regional: EC2, Lambda, RDS, S3 buckets.
