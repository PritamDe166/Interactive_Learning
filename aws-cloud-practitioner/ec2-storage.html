EC2 Instance Storage

  • EBS: a network drive for one instance, locked to one AZ, survives the instance.
  • Instance store: a fast disk inside the host. Lost when the instance stops or terminates.
  • EFS (Linux) and FSx (Windows, Lustre…): shared file systems for many instances across AZs.
  • Snapshots back up EBS and move it across AZs and Regions. An AMI = snapshots + launch recipe.

Snapshot vs AMI

A snapshot is one volume's data. An AMI is snapshots plus a recipe: architecture, boot settings, volume mapping, launch permissions. You launch instances from an AMI, never from a snapshot.

Snapshot features

Archive tier: up to 75% cheaper, 24–72 h to restore. Recycle Bin: rules keep deleted snapshots and AMIs recoverable for a retention period. Copy to another Region for DR.

AMIs and Image Builder

AMIs come from AWS (Amazon Linux, Windows), the Marketplace, or you ("golden image" for faster boot). EC2 Image Builder automates build → test → distribute on a schedule; you pay only for the resources it uses.

Added

Why a snapshot can cross AZs but a volume can't: the volume's blocks sit in one AZ; a snapshot is stored in S3-backed storage at Region level. Restoring makes an independent copy, not a synced replica.

Added

More storage classes and options than the course lists: EFS has Standard, Infrequent Access and Archive, moved automatically by lifecycle policy. FSx also offers NetApp ONTAP and OpenZFS. For the exam, map "Windows/SMB/AD" → FSx for Windows. FSx for Lustre ("HPC") is on the CLF-C02 out-of-scope list, so expect it only as a distractor.

Corrected

FSx for Lustre isn't "Region-wide" as the summary table says: a Lustre file system runs in a single AZ (it's built for speed, not HA); durability comes from linking it to S3. FSx for Windows can be Multi-AZ.

Added

Shared responsibility for storage: AWS replicates EBS within the AZ and runs the hardware; you take snapshots, choose encryption, set Delete on termination, and accept that instance-store data can vanish. See Shared Responsibility.

Check yourself

Answer out loud before you open each card.

Can an EBS volume in AZ a be attached to an instance in AZ b?Show answer

No. Snapshot it, then create a new volume from the snapshot in AZ b.

You stop an instance. What happens to instance-store data?Show answer

It's lost. Instance store survives a reboot, but not stop, terminate or host failure.

By default, what happens to the root EBS volume on termination? An extra data volume?Show answer

Root: deleted (Delete on termination = on). Extra volume: kept (off by default).

100 Linux instances across 3 AZs need the same files. Which service?Show answer

EFS. (If they were Windows with SMB and Active Directory: FSx for Windows File Server.)

"Storage for high performance computing" in the course means…?Show answer

FSx for Lustre (Linux + cluster). It's out of scope for CLF-C02 itself, but the course uses it.

Which service automates building, testing and distributing AMIs?Show answer

EC2 Image Builder.
