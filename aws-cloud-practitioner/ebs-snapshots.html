EBS snapshots

  • A snapshot is a point-in-time backup of one EBS volume, stored by AWS (in S3, behind the scenes).
  • Snapshots are incremental: after the first, only changed blocks are saved.
  • Restore a snapshot as a new volume in any AZ, or copy it to another Region for disaster recovery.
  • Archive tier cuts storage cost up to 75%; the Recycle Bin catches accidental deletes.

Points to remember

  1. A snapshot is a backup of an EBS volume at a point in time. You don't have to detach the volume, but it's recommended for consistency.
  2. Snapshots are stored by AWS (in S3, not in a bucket you can see) and are Region-level: they are not tied to an AZ.
  3. Incremental: the first snapshot copies all written blocks; later ones store only the blocks changed since the last one.
  4. Move a volume to another AZ: snapshot → Create volume from snapshot in the target AZ. The new volume is a copy, not kept in sync.
  5. Copy a snapshot to another Region for disaster recovery or to launch there.
  6. EBS Snapshot Archive: up to 75% cheaper storage, but restoring takes 24 to 72 hours. Use for backups kept 90+ days and rarely needed.
  7. Recycle Bin: with a retention rule, deleted snapshots (and AMIs, volumes) are kept for a period you choose (snapshots: 1 day to 1 year) and can be recovered. Without a rule, delete is permanent.
  8. A locked retention rule can't be edited or deleted until it is unlocked and a delay of 7 to 30 days passes: protection against someone deleting your safety net.
  9. When restoring you can change the volume type, size (bigger), and turn on encryption.

Which snapshot feature?

In the console

Snapshot, restore, archive and recover (from the course hands-on)
  1. EC2 → Volumes → select the volume → Actions → Create snapshot, add a description (e.g. DemoSnapshots).
  2. Snapshots page: wait for status Completed.
  3. Actions → Copy snapshot: pick a destination Region (for DR).
  4. Actions → Create volume from snapshot: choose type, size and a different AZ; optionally encrypt and tag. Check it under Volumes.
  5. Recycle Bin → Create retention rule: resource type EBS Snapshots, all resources, retention 1 day, leave Rule lock off for the demo.
  6. Select the snapshot → Archive snapshot (storage tier changes from Standard to Archive).
  7. Delete snapshot. It vanishes from Snapshots but appears in Recycle Bin → Resources; select it → Recover. It's back in Snapshots.

Cheat-sheet

  • Back up an EBS volume→EBS snapshot
  • Same data in another AZ→Create volume from snapshot in that AZ
  • Disaster recovery in another Region→Copy snapshot to that Region
  • Keep for years, rarely restore, cheapest→EBS Snapshot Archive (24–72 h restore)
  • Protect against accidental deletion→Recycle Bin retention rule
  • Automate snapshot schedules→Data Lifecycle Manager / AWS Backup

Check yourself

Is a snapshot tied to an AZ?Show answer

No. It is stored at the Region level, which is why it can be restored into any AZ of that Region.

Why is the second snapshot much smaller than the first?Show answer

Snapshots are incremental: only blocks changed since the last snapshot are stored.

A restore is needed within an hour. Is the Archive tier OK?Show answer

No. Archived snapshots take 24–72 hours to restore.

You deleted a snapshot and no rule existed. Can the Recycle Bin help?Show answer

No. The rule must exist before the deletion.

How do you get an EBS volume's data into another Region?Show answer

Snapshot it, copy the snapshot to that Region, create a volume there.

Does a restored volume stay in sync with the original?Show answer

No. It is an independent copy from that moment. For a shared live file system, use EFS.
