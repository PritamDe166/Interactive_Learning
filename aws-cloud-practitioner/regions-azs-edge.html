Regions, AZs & edge locations

  • A Region is a geographic area (such as ap-south-1, Mumbai). Most services are regional: you pick the Region for each resource.
  • Each Region has 3 or more Availability Zones. An AZ is one or more data centres with its own power and network, isolated from the others.
  • Spreading your app across AZs keeps it running when one AZ fails.
  • Edge locations (points of presence) sit in many more cities. You don't run servers there; services like CloudFront cache content there, close to users.

Points to remember

  1. A Region is a geographic area with a code (us-east-1, ap-south-1). Most services are regional: resources live in the Region you choose.
  2. Each Region has three or more Availability Zones. An AZ = one or more discrete data centres with redundant power, networking and connectivity, isolated from other AZs and linked by low-latency networking.
  3. Multi-AZ deployment = high availability inside a Region. Multi-Region = protection against a whole-Region disaster.
  4. Edge locations (points of presence) sit close to users and serve CloudFront caching; you don't run EC2 there.
  5. Choose a Region by compliance (data residency) first, then latency, service availability and price.
  6. Global services: IAM, Route 53, CloudFront, WAF. Regional: EC2, Lambda, RDS, Elastic Beanstalk, S3 buckets.
  7. Local Zones, Wavelength Zones and Outposts run AWS closer to users or on-premises (exam guide Task 3.2).
  8. The exam tests the structure, not the counts (39 Regions and 124 AZs in October 2026).

Exam cheat-sheet

  • Geographic area, you choose it per resource→Region
  • One or more isolated data centres inside a Region→Availability Zone
  • Survive a data-centre failure→Deploy across multiple AZs
  • Survive a whole-Region disaster→Deploy in multiple Regions
  • Cache content close to users→Edge locations (CloudFront)
  • Data must stay in a country→Choose that Region (compliance first)
  • Can I run EC2 at an edge location?→No (look at Local Zones / Wavelength)

An edge location is not an Availability Zone. Your EC2 instances run in a Region's AZs. CloudFront caches and serves copies at the edge while the origin stays in the Region.

Other places AWS can run your workload (exam guide task 3.2): Local Zones (a Region extension in a large city for single-digit-millisecond latency), Wavelength Zones (inside 5G telecom networks) and Outposts (AWS racks in your own data centre).

An AZ is not necessarily one building. It can be several data centres; AWS doesn't expose the physical detail.

What is an Availability Zone, in one sentence?Show answer

One or more discrete data centres inside a Region, with independent power and networking, isolated from the other AZs and linked to them by low-latency networking.

How do you keep an app running if one data centre floods?Show answer

Run it in at least two Availability Zones behind a load balancer.

Patient data must legally stay in India. Which Region factor decides first?Show answer

Compliance / data residency. Latency, available services and price only matter among Regions that are allowed.

Is an edge location a place to run your EC2 instances near users?Show answer

No. Edge locations serve CloudFront and other edge services. For compute near users, look at Local Zones or Wavelength.

You create an EC2 instance in ap-south-1. Can you see it while the console is set to eu-west-1?Show answer

No. EC2 is regional. Switch the console to ap-south-1.

Name three global services.Show answer

Any three of IAM, Route 53, CloudFront, WAF.
