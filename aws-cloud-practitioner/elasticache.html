Amazon ElastiCache

  • ElastiCache is a managed in-memory data store (Valkey, Redis OSS or Memcached) with sub-millisecond reads.
  • Put it in front of a database to cut load from repeated reads, or use it as a shared session store.
  • The app checks the cache first and fills it on a miss (cache-aside); you write that logic.
  • AWS handles patching, monitoring, failure recovery and backups.

In terms you know

AWSClosest thing you knowThe difference
ElastiCacheA Redis server, or IMemoryCache shared by every web serverManaged, replicated across AZs, sized or serverless.
Session storeASP.NET session state on a state server instead of in-processSame purpose: servers stay stateless.

Points to remember

  1. ElastiCache = managed in-memory cache/database: Valkey, Redis OSS, Memcached.
  2. Sub-millisecond latency; best for read-heavy, repeated queries.
  3. Reduces load on databases such as RDS; also used for sessions, leaderboards, rate limiting.
  4. Applications need code changes to use a cache (cache-aside, TTL, invalidation).
  5. AWS manages provisioning, patching, monitoring, failure recovery, backups.
  6. DAX is the DynamoDB-only cache; ElastiCache works with anything.

Cheat-sheet

  • In-memory, sub-millisecond, cache→ElastiCache
  • Reduce database load from repeated reads→ElastiCache
  • Shared session store→ElastiCache
  • Cache only for DynamoDB→DAX
  • Engines→Valkey, Redis OSS, Memcached

Reference

ElastiCacheDAX
CachesAny source (RDS, Aurora, APIs…)DynamoDB only
LatencySub-millisecondMicroseconds
Code changesYes, cache logic in the appMinimal (DynamoDB-compatible API)

Not a replacement database. If a question needs a durable primary database, a cache is the wrong answer (MemoryDB, a durable in-memory database, is out of scope for CLF-C02).
