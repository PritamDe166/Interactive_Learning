Synchronous vs Asynchronous Communication

  • Synchronous: one app calls another directly and waits. Simple, but tightly coupled.
  • Asynchronous (event-based): the sender puts a message in a queue or publishes an event; the receiver handles it later.
  • Decoupling absorbs traffic spikes and lets each side scale independently.
  • AWS: SQS (queues), SNS (pub/sub), Kinesis (real-time streams).

Points to remember

  1. Synchronous = direct call, caller waits; tight coupling.
  2. Asynchronous = message in a queue or event on a topic; loose coupling (decoupled).
  3. Under a spike, a direct call can overwhelm the receiver; a queue holds the backlog.
  4. Decoupled services scale independently.
  5. SQS: queue model. SNS: pub/sub. Kinesis: real-time streaming.

Cheat-sheet

  • Decouple applications→SQS / SNS / Kinesis
  • Queue messages until processed→SQS
  • One message to many subscribers→SNS
  • Real-time data streams→Kinesis
  • Absorb a traffic spike→A queue (asynchronous)

Why does a queue help during a sudden spike?Show answer

It holds the messages so the receiver can process them at its own pace; nothing is lost.

What does "decoupled" mean?Show answer

The services don't call each other directly, so one can be slow or down without breaking the other.
