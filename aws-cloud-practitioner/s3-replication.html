AWS CLF-C02 / Amazon S3 / 5 · Domain 3 Technology

S3 Replication: CRR & SRR

  • Replication copies new objects to another bucket automatically and asynchronously.
  • CRR (Cross-Region) copies to another Region; SRR (Same-Region) to another bucket in the same Region. Both can cross accounts.
  • It needs versioning on both buckets and an IAM role for S3.
  • It is not retroactive: existing objects need S3 Batch Replication.

Points to remember

  1. Replication = automatic, asynchronous copying of objects between buckets, in the same or different accounts.
  2. CRR (different Regions): compliance, disaster recovery, lower-latency access, cross-account copies.
  3. SRR (same Region): log aggregation, live copies between production and test accounts, data residency.
  4. Requirements: versioning on source and destination, and an IAM role for S3.
  5. Only new objects replicate after the rule is set up. Use S3 Batch Replication for existing objects.
  6. No time guarantee by default; Replication Time Control gives a 15-minute SLA.
  7. Delete markers replicate only if you enable it; version deletes never replicate.
  8. You pay for the copy's storage, the requests and (for CRR) the data transfer.

In the console

Set up Cross-Region Replication (outline)
  1. Create a source bucket in one Region and a destination bucket in another, both with versioning enabled.
  2. Source bucket → Management → Replication rules → Create replication rule: apply to all objects, choose the destination bucket, let S3 create a new IAM role.
  3. When asked whether to replicate existing objects, say no (or run a Batch Replication job).
  4. Upload a file to the source; a few seconds later it appears in the destination with the same version ID.

Cheat-sheet

  • Copy objects to another Region automatically→CRR
  • Aggregate logs in the same Region→SRR
  • Prerequisite for replication→Versioning on both buckets
  • Replicate objects that already exist→S3 Batch Replication
  • Guaranteed replication time→Replication Time Control (15 min)
  • Replication: synchronous or asynchronous?→Asynchronous

Versioning vs replication. Versioning keeps older copies of an object inside one bucket; replication keeps copies in another bucket. Replication builds on versioning.

Different storage class at the destination. A rule can write the copies straight into a cheaper class (for example Glacier) for a backup copy.

Same-Region Replication.

No, asynchronous. Use Replication Time Control for a 15-minute SLA.

Yes, for both CRR and SRR.
