Elastic Load Balancing

  • A load balancer is one front door (a single DNS name) that spreads requests across many instances in several AZs.
  • Health checks find broken instances and stop sending traffic to them.
  • It can end HTTPS for you, and your instances can accept traffic only from the load balancer.
  • Four types: ALB (HTTP, layer 7), NLB (TCP/UDP, layer 4, static IP), GWLB (firewall appliances, layer 3), and the previous-generation Classic.

Points to remember

  1. Elastic Load Balancing (ELB) is a managed service: AWS keeps it running, patches it and scales it. You configure it.
  2. It gives one DNS name for the app and spreads the load across instances in several AZs.
  3. Health checks (for example HTTP GET /health must return 200) stop traffic to unhealthy instances.
  4. It can terminate HTTPS (SSL/TLS) with a certificate from ACM, so instances don't each need one.
  5. Instances can allow traffic only from the load balancer's security group, so users can't reach them directly.
  6. ALB: HTTP, HTTPS, gRPC; routes by path, host name, header or query string; targets include EC2, containers, IPs and Lambda.
  7. NLB: TCP, UDP, TLS; millions of requests per second, ultra-low latency, a static IP per AZ (you can use Elastic IPs).
  8. GWLB: sends traffic through third-party firewalls or intrusion-detection appliances (GENEVE, port 6081).
  9. Classic Load Balancer: previous generation, still supported for existing apps; not for new designs.

In the console

Create an Application Load Balancer (outline)
  1. Launch two EC2 instances (Amazon Linux 2023) with a small web server in their user data.
  2. EC2 → Target groups → Create: type Instances, protocol HTTP 80, health check path /. Register both instances.
  3. EC2 → Load balancers → Create → Application Load Balancer: internet-facing, IPv4, pick at least two AZs.
  4. Give it a new security group that allows HTTP 80 from anywhere. Add a listener on HTTP 80 that forwards to the target group.
  5. Open the load balancer's DNS name and refresh: the response comes from one instance, then the other.
  6. Lock down the instances: change their security group to allow port 80 only from the load balancer's security group.
  7. Clean up: delete the load balancer, the target group and the instances (a load balancer is billed by the hour).

Cheat-sheet

  • HTTP or HTTPS, route by path or host name→Application Load Balancer
  • TCP or UDP, millions of requests, ultra-low latency→Network Load Balancer
  • Static IP or Elastic IP needed→Network Load Balancer
  • Run traffic through firewall or IDS appliances→Gateway Load Balancer
  • Lambda function as a target→Application Load Balancer
  • Stop sending traffic to broken instances→Health checks
  • Certificate on the load balancer, not on every server→TLS termination with ACM
  • "Old" load balancer in an existing app→Classic LB, previous generation

Cross-zone load balancing. With it on, each load balancer node spreads requests across healthy targets in all enabled AZs, not just its own. It is always on for an ALB (it can be switched off per target group) and off by default for NLB and GWLB.

Deregistration delay (connection draining). When an instance is removed, the load balancer stops sending it new requests but lets current ones finish. The default wait is 300 seconds.

Sticky sessions send one user's requests to the same instance using a cookie. They help an app that keeps session state in memory, but they can unbalance the load; storing sessions outside the instance (for example in ElastiCache or DynamoDB) is the cleaner fix.

Pricing. You pay per hour for each load balancer plus a usage charge (load balancer capacity units for ALB and NLB). Delete practice load balancers when you are done.

Often paired with: Route 53 (a friendly domain name pointing at the load balancer), ACM (certificates) and AWS WAF (a web application firewall attached to an ALB).

Check yourself

Answer out loud before you open each card.

Your API needs to send /orders and /payments to different services. Which load balancer?Show answer

ALB. Path-based routing needs layer 7 (HTTP).

A partner can only allow-list fixed IP addresses. Which load balancer?Show answer

NLB. It has a static IP per AZ and can use Elastic IPs. ALB gives a DNS name whose IPs change.

An instance's app crashes. What stops users being sent to it?Show answer

The load balancer's health check marks it unhealthy and stops routing to it. An Auto Scaling group can then replace it.

How do you stop users bypassing the load balancer and calling the instances directly?Show answer

Let the instances' security group allow traffic only from the load balancer's security group.

All traffic must pass through a third-party firewall appliance. Which load balancer?Show answer

Gateway Load Balancer (layer 3, GENEVE).

Who patches and scales the load balancer itself?Show answer

AWS. ELB is a managed service; you only configure listeners, rules, target groups and health checks.
