EBS volumes

  • Amazon EBS (Elastic Block Store) is the disk of an EC2 instance, but it is a network drive, not a disk inside the server.
  • It is persistent: data stays when the instance stops, and can stay after it is terminated.
  • A volume lives in one Availability Zone and attaches only to instances in that AZ.
  • You provision size (GiB) and performance (IOPS) up front and pay for what you provision.

Points to remember

  1. EBS = network drive for EC2. Data travels over the AWS network, so there is a little latency, but the drive can move between instances.
  2. Persistent: survives stop/start, and survives termination unless Delete on termination is on.
  3. Bound to one AZ. A volume in us-east-1a can't attach to an instance in us-east-1b. To move it: snapshot → new volume in the other AZ.
  4. One instance can have many volumes; a volume is normally attached to one instance at a time (Multi-Attach exists only for io1/io2, out of exam scope).
  5. You provision capacity (GiB) and performance (IOPS, throughput) and are billed for what you provision, attached or not. Both can be increased later.
  6. Delete on termination defaults: root volume = Yes (deleted), extra volumes = No (kept). Turn it off on the root to keep it.
  7. States: creating → available (not attached) → in-use (attached).
  8. Attaching is not the end: the OS still has to format and mount a new data volume.
  9. Volume families: gp3/gp2 general SSD, io2/io1 provisioned-IOPS SSD (databases), st1 throughput HDD, sc1 cold HDD. Only SSD types can be a boot volume.

In the console

Create, attach and clean up a volume (from the course hands-on)
  1. EC2 → select the instance → Storage tab: the root device is an 8 GiB EBS volume. Note the instance's AZ under Networking (e.g. eu-west-1b).
  2. Left menu Elastic Block Store → Volumes → Create volume: type gp3 (or gp2), size 2 GiB, same AZ as the instance.
  3. Refresh until the state is available. Then Actions → Attach volume, choose the instance. State becomes in-use; the Storage tab now lists two block devices.
  4. Create another volume in a different AZ: it becomes available, but the instance doesn't appear in the Attach list.
  5. Delete the test volume: Actions → Delete volume (only when it is available).
  6. In the launch wizard, Storage → Advanced shows Delete on termination per volume. Terminate the instance: the root volume disappears, the extra volume stays available.

Cheat-sheet

  • Persistent disk for one EC2 instance→EBS volume
  • Move a volume to another AZ→Snapshot, then create a volume in that AZ
  • Keep the root disk after terminate→Delete on termination = No
  • "Network USB stick", "AZ-locked"→EBS
  • Database needing guaranteed high IOPS→EBS io2 / io1 (Provisioned IOPS)
  • Cheapest general SSD→gp3

For the exam, numbers are rarely asked, but you will see "which EBS type for a database" (io2) and "cheapest storage for infrequent data" (sc1).

Check yourself

Why is EBS called a network drive?Show answer

It isn't inside the host server; the instance reaches it over the AWS network. That's why it can be detached and attached to another instance.

Can a volume in us-east-1a attach to an instance in us-east-1b?Show answer

No. Take a snapshot and create a new volume from it in us-east-1b.

You terminate an instance with a root and an extra volume, defaults unchanged. What's left?Show answer

The extra volume, now available. The root volume is deleted.

Does an unattached volume cost money?Show answer

Yes. You pay for provisioned GiB (and IOPS) whether it's attached or not.

The instance is stopped. Is the EBS data still there?Show answer

Yes. Stop keeps EBS volumes (unlike instance store).

You attached a new volume but don't see it in Linux. Why?Show answer

The OS must format and mount it first; attaching only connects the device.
