AWS CLF-C02 · IAM · Domain 2 Security & Compliance (Tasks 2.1, 2.3)

IAM best practices & shared responsibility

  • Lock the root user away (MFA, no access keys). Give each person their own identity; never share.
  • Manage permissions through groups with least privilege; use roles for AWS services.
  • Enforce a password policy and MFA; keep access keys secret and rotated, or avoid them.
  • Audit with the credential report and Access Advisor. AWS runs IAM; configuring it well is your responsibility.

Points to remember

  1. Don't use the root user for daily work. MFA on root, no root access keys, credentials stored safely.
  2. One identity per person. Never share users, passwords, keys or MFA devices. (At company scale AWS recommends IAM Identity Center for people.)
  3. Groups for permissions; least privilege; review and remove what's unused.
  4. Password policy: minimum length, upper/lower case, numbers, symbols, expiry (1–1,095 days), prevent reuse (last 1–24). Default: 8–128 characters, 3 of 4 character types. It doesn't apply to root or to access keys, and there's no lockout setting.
  5. MFA = password (something you know) + device (something you have). Types: passkeys / FIDO security keys (phishing-resistant, preferred), virtual authenticator apps, hardware TOTP tokens. Up to 8 devices per user. SMS MFA is no longer offered.
  6. Roles for AWS services (EC2, Lambda, CloudFormation): no keys on servers.
  7. Access keys: secret like a password; never commit or share; rotate; delete unused. Prefer temporary credentials.
  8. Audit: credential report (account credentials) and Access Advisor (unused permissions).
  9. Store app secrets in AWS Secrets Manager or Systems Manager Parameter Store, never in code.
  10. Shared responsibility for IAM: AWS runs the IAM service and its infrastructure; you create users, groups, roles and policies, enable MFA, rotate keys, review access and apply least privilege.
